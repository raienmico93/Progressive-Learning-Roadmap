# DOM Events — Comprehensive Cheat Sheet

---

## Topic Overview

### Definitions

**Core Definition:** A DOM event is an action or occurrence that happens in the browser — such as a user clicking a button, pressing a key, or a page finishing loading — which JavaScript can listen for and respond to.

**Technical Definition:** Per MDN, the `Event` interface represents an event that takes place in the DOM. Events can be triggered by user actions (e.g., clicking a mouse button or pressing a keyboard key) or generated by APIs to represent the progress of an asynchronous task. They can also be triggered programmatically, such as by calling the `HTMLElement.click()` method or by defining an event and dispatching it using `EventTarget.dispatchEvent()`. Each event is represented by an object based on the `Event` interface, and may have additional custom fields and/or functions to provide information about what happened.

**Beginner-Friendly Explanation:** An event is something that happens on a web page — a click, a keypress, a scroll, a mouse movement. JavaScript can "listen" for these events and run code when they occur. This is what makes web pages interactive: instead of just displaying static content, the page responds to what the user does.

### Key Characteristics

- **Event-driven:** Web pages respond to user actions and system events rather than running sequentially.
- **Event objects:** Every event is represented by an object containing information about the event (what happened, where, on which element).
- **Event propagation:** Events travel through the DOM tree in three phases: capturing, target, and bubbling.
- **Event listeners:** Functions registered to respond to specific events on specific targets.
- **Delegation:** Events can be handled at a parent level using bubbling, reducing the number of listeners needed.
- **Cancellable:** Some events have default browser behaviours (e.g., link navigation) that can be prevented.

### Prerequisites

- Understanding of the DOM tree, nodes, and elements.
- Familiarity with selecting elements (`querySelector`, `getElementById`).
- Basic knowledge of JavaScript functions and callbacks.

### Related Programming Areas

- **Interactive UI:** Buttons, forms, menus, and other interactive components.
- **Form validation:** Responding to input, change, and submit events.
- **Keyboard shortcuts:** Handling keydown and keyup events.
- **Touch and gesture:** Handling touchstart, touchmove, and touchend on mobile.
- **Drag and drop:** Implementing drag-and-drop interfaces.
- **Custom events:** Communication between components.

## Event Types

### Definitions

**Core Definition:** Event types are the categories of events that the DOM can dispatch, each representing a specific kind of user interaction or system occurrence.

**Technical Definition:** Per MDN, there are many types of events, some of which use other interfaces based on the main `Event` interface. `Event` itself contains the properties and methods which are common to all events. Each event type is documented with a table linking to its associated event interface and other related information.

### Purposes

- To categorise interactions so that code can respond to specific kinds of events.
- To provide a consistent API for handling different interaction modalities.
- To enable developers to attach handlers only to the events they care about.

### Mouse Events

**Definition:** Events triggered by mouse interactions.

| Event | Description |
|-------|-------------|
| `click` | Fired when a pointing device button is pressed and released on an element |
| `dblclick` | Fired when a pointing device button is clicked twice on an element |
| `mousedown` | Fired when a pointing device button is pressed on an element |
| `mouseup` | Fired when a pointing device button is released on an element |
| `mousemove` | Fired when a pointing device is moved while over an element |
| `mouseover` | Fired when a pointing device is moved onto an element or one of its children |
| `mouseout` | Fired when a pointing device is moved off an element or one of its children |
| `mouseenter` | Fired when a pointing device is moved onto an element (does not bubble) |
| `mouseleave` | Fired when a pointing device is moved off an element (does not bubble) |

### Keyboard Events

**Definition:** Events related to using a keyboard. Used to notify when keys are moved up, down, or pressed down.

| Event | Description |
|-------|-------------|
| `keydown` | Fired when a key is pressed down |
| `keypress` | Fired when a key that produces a character value is pressed down (deprecated) |
| `keyup` | Fired when a key is released |

### Form Events

**Definition:** Events related to forms being constructed, reset, and submitted.

| Event | Description |
|-------|-------------|
| `submit` | Fired when a form is submitted |
| `reset` | Fired when a form is reset |
| `change` | Fired when the value of a form element has changed |
| `input` | Fired when the value of an input element has changed |
| `focus` | Fired when an element receives focus (does not bubble) |
| `blur` | Fired when an element loses focus (does not bubble) |
| `focusin` | Fired when an element receives focus (bubbles) |
| `focusout` | Fired when an element loses focus (bubbles) |

### Document Events

**Definition:** Events that occur on the `document` object.

| Event | Description |
|-------|-------------|
| `DOMContentLoaded` | Fired when the HTML document has been completely parsed and deferred scripts have executed |
| `readystatechange` | Fired when the `document.readyState` property changes |
| `visibilitychange` | Fired when the visibility state of the document changes |

### Window Events

**Definition:** Events that occur on the `window` object.

| Event | Description |
|-------|-------------|
| `load` | Fired when the whole page has loaded, including all dependent resources |
| `resize` | Fired when the window has been resized |
| `scroll` | Fired when the document view has been scrolled |
| `beforeunload` | Fired when the window is about to be unloaded |
| `unload` | Fired when the document is being unloaded |

### Touch Events

**Definition:** Events triggered by touch interactions on touch-enabled devices.

| Event | Description |
|-------|-------------|
| `touchstart` | Fired when one or more touch points are placed on the touch surface |
| `touchmove` | Fired when one or more touch points are moved along the touch surface |
| `touchend` | Fired when one or more touch points are removed from the touch surface |
| `touchcancel` | Fired when one or more touch points have been disrupted |

### Pointer Events

**Definition:** Events triggered by any pointing device (mouse, pen, touch).

| Event | Description |
|-------|-------------|
| `pointerdown` | Fired when a pointer becomes active |
| `pointerup` | Fired when a pointer is no longer active |
| `pointermove` | Fired when a pointer changes coordinates |
| `pointerover` | Fired when a pointer enters an element's boundaries |
| `pointerout` | Fired when a pointer leaves an element's boundaries |

### Drag Events

**Definition:** Events related to dragging and dropping. Drag and Wheel events are derived from mouse events.

| Event | Description |
|-------|-------------|
| `dragstart` | Fired when the user starts dragging an element |
| `drag` | Fired when an element is being dragged |
| `dragend` | Fired when a drag operation ends |
| `dragenter` | Fired when a dragged element enters a valid drop target |
| `dragleave` | Fired when a dragged element leaves a valid drop target |
| `dragover` | Fired when a dragged element is over a valid drop target |
| `drop` | Fired when an element is dropped on a valid drop target |

### Clipboard Events

**Definition:** Events related to the Clipboard API. Used to notify when content is cut, copied, or pasted.

| Event | Description |
|-------|-------------|
| `copy` | Fired when the user initiates a copy action |
| `cut` | Fired when the user initiates a cut action |
| `paste` | Fired when the user initiates a paste action |

### Media Events

**Definition:** Events related to media elements (`<audio>`, `<video>`).

| Event | Description |
|-------|-------------|
| `play` | Fired when playback has begun |
| `pause` | Fired when playback has been paused |
| `ended` | Fired when playback has stopped because the end was reached |
| `timeupdate` | Fired when the current playback position has changed |
| `volumechange` | Fired when the volume has changed |

### Animation Events

**Definition:** Events related to the Web Animations API. Used to respond to changes in animation state (e.g., when an animation starts or ends).

| Event | Description |
|-------|-------------|
| `animationstart` | Fired when a CSS animation has started |
| `animationend` | Fired when a CSS animation has completed |
| `animationiteration` | Fired when a CSS animation has completed an iteration |
| `animationcancel` | Fired when a CSS animation has been cancelled |

### Transition Events

**Definition:** Events related to CSS transitions. Provide notification when a CSS transition starts, stops, or is cancelled.

| Event | Description |
|-------|-------------|
| `transitionrun` | Fired when a CSS transition is created |
| `transitionstart` | Fired when a CSS transition has started |
| `transitionend` | Fired when a CSS transition has completed |
| `transitioncancel` | Fired when a CSS transition has been cancelled |

## Event Listeners

### Definitions

**Core Definition:** An event listener is a function registered to be called when a specific event occurs on a specific target.

**Technical Definition:** Per MDN, the `addEventListener()` method of the `EventTarget` interface attaches a function to be called whenever the specified event is delivered to the target. Common targets are `Element`, `Document`, and `Window`, but any object supporting events can be a target. `addEventListener()` works by adding a function or object that implements `EventListener` to the list of event handlers for the specified event type on the `EventTarget`.

### Purposes

- To respond to user interactions and system events.
- To attach multiple handlers to the same event on the same target.
- To control when handlers are invoked (capturing, bubbling, once, passive).
- To detach handlers when they are no longer needed.

### `addEventListener()`

**Syntax Rules and Structure:**
```js
target.addEventListener(type, listener, options);
target.addEventListener(type, listener, useCapture);
```

**Component Breakdown:**
- `type`: A case-sensitive string representing the event type to listen for (e.g., `"click"`, `"keydown"`).
- `listener`: The object that receives the event notification. This must be an object implementing `EventListener` or a JavaScript function.
- `options` (optional): An object specifying characteristics of the event listener:
  - `capture` (boolean): If `true`, the listener is invoked during the capturing phase.
  - `once` (boolean): If `true`, the listener is automatically removed after its first invocation.
  - `passive` (boolean): If `true`, the listener will never call `preventDefault()`.
- `useCapture` (optional): A boolean indicating whether to use the capturing phase. Defaults to `false` (bubbling).

**Annotated Code Example:**
```js
// Step 1: Select a button.
const button = document.querySelector("button");

// Step 2: Define a handler.
function handleClick(event) {
  console.log("Button clicked!", event.type);
}

// Step 3: Attach the listener.
button.addEventListener("click", handleClick);

// Step 4: The handler runs when the button is clicked.
```
**Expected Output:**
```
Button clicked! click
```

### `removeEventListener()`

**Core Definition:** `removeEventListener()` removes an event listener previously registered with `addEventListener()`.

**Technical Definition:** Per MDN, `removeEventListener()` removes an event listener from the `EventTarget`. The listener must be the same function reference that was used in `addEventListener()`. If a listener was registered twice, once with capture and once without, each must be removed separately. The only option checked by `removeEventListener()` is the `capture`/`useCapture` flag.

**Syntax Rules and Structure:**
```js
target.removeEventListener(type, listener, options);
target.removeEventListener(type, listener, useCapture);
```

**Annotated Code Example:**
```js
const button = document.querySelector("button");
function handleClick() { console.log("Clicked"); }

// Add the listener.
button.addEventListener("click", handleClick);

// Remove the listener.
button.removeEventListener("click", handleClick);
```

### `dispatchEvent()`

**Core Definition:** `dispatchEvent()` dispatches an event to the `EventTarget`, invoking the affected event listeners in the appropriate order.

**Technical Definition:** Per MDN, `dispatchEvent()` sends an event to the `EventTarget`. The event can be created using the `Event` constructor or `CustomEvent` constructor.

**Syntax Rules and Structure:**
```js
target.dispatchEvent(event);
```

**Annotated Code Example:**
```js
const button = document.querySelector("button");
button.addEventListener("click", () => console.log("Handled"));

const event = new Event("click");
button.dispatchEvent(event);
```
**Expected Output:**
```
Handled
```

## Event Objects

### Definitions

**Core Definition:** An event object is an object created by the browser when an event occurs, containing information about the event and methods for controlling its behaviour.

**Technical Definition:** Per MDN, the `Event` interface represents an event which takes place in the DOM. It contains properties and methods common to all events.

### Key Properties

| Property | Description |
|----------|-------------|
| `type` | The name of the event (e.g., `"click"`, `"keydown"`) |
| `target` | The element on which the event was dispatched |
| `currentTarget` | The element to which the event handler is attached |
| `eventPhase` | The current phase of the event flow (1 = capturing, 2 = target, 3 = bubbling) |
| `bubbles` | Whether the event bubbles up through the DOM |
| `cancelable` | Whether the event can be cancelled |
| `defaultPrevented` | Whether `preventDefault()` has been called |

### `target` vs `currentTarget`

**Definition:** `target` identifies the element on which the event occurred; `currentTarget` identifies the element to which the event handler is attached.

**Example:**
```html
<div id="parent">
  <button id="child">Click me</button>
</div>
```
```js
document.getElementById("parent").addEventListener("click", (event) => {
  console.log("target:", event.target.id);        // "child"
  console.log("currentTarget:", event.currentTarget.id); // "parent"
});
```
**Expected Output:**
```
target: child
currentTarget: parent
```

### Key Methods

| Method | Description |
|--------|-------------|
| `preventDefault()` | Prevents the default browser behaviour for the event |
| `stopPropagation()` | Stops the event from propagating further in the capturing or bubbling phases |
| `stopImmediatePropagation()` | Prevents other listeners of the same event from being called and stops propagation |

### `preventDefault()`

**Definition:** `preventDefault()` tells the browser not to perform the default action associated with the event (e.g., following a link, submitting a form).

**Annotated Code Example:**
```js
const link = document.querySelector("a");
link.addEventListener("click", (event) => {
  event.preventDefault();
  console.log("Navigation prevented");
});
```

### `stopPropagation()` vs `stopImmediatePropagation()`

**Definition:** `stopPropagation()` prevents the event from bubbling up to parent elements. `stopImmediatePropagation()` does the same, but also prevents other listeners on the **same element** from being called.

**Example:**
```js
const parent = document.getElementById("parent");
const child = document.getElementById("child");

parent.addEventListener("click", () => console.log("Parent"));
child.addEventListener("click", (e) => {
  e.stopPropagation();
  console.log("Child");
});
// Clicking child logs "Child" only (not "Parent").
```

## Event Phases

### Definitions

**Core Definition:** Event propagation is the process by which an event travels through the DOM tree in three phases: capturing, target, and bubbling.

**Technical Definition:** Per MDN, the `eventPhase` property returns an integer representing the current phase of the event flow. The possible values are `Event.CAPTURING_PHASE` (1), `Event.AT_TARGET` (2), and `Event.BUBBLING_PHASE` (3).

### Capturing Phase

**Definition:** The event propagates from the `Window` down through the document tree to the target's parent. Event listeners registered with `capture: true` are invoked during this phase.

### Target Phase

**Definition:** The event has arrived at the target element. If `bubbles` is `false`, the event flow ends at this phase.

### Bubbling Phase

**Definition:** The event propagates back up through the target's ancestors in reverse order, starting with the parent and eventually reaching the `Window`. This is called bubbling. Listeners registered without `capture: true` are invoked during this phase.

### Annotated Code Example

```html
<div id="outer">
  <div id="inner">
    <button id="btn">Click</button>
  </div>
</div>
```
```js
const outer = document.getElementById("outer");
const inner = document.getElementById("inner");
const btn = document.getElementById("btn");

// Capturing phase (outer to inner):
outer.addEventListener("click", () => console.log("outer capture"), true);
inner.addEventListener("click", () => console.log("inner capture"), true);

// Bubbling phase (inner to outer):
btn.addEventListener("click", () => console.log("button bubble"));
inner.addEventListener("click", () => console.log("inner bubble"));
outer.addEventListener("click", () => console.log("outer bubble"));
```
**Expected Output (on clicking the button):**
```
outer capture
inner capture
button bubble
inner bubble
outer bubble
```

## Event Delegation

### Definitions

**Core Definition:** Event delegation is a technique where a single event listener is attached to a parent element instead of individual listeners on each child element. The listener uses event bubbling to handle events from children.

**Technical Definition:** Per MDN, event delegation makes use of two features of JavaScript events: event bubbling and the `target` element. Instead of adding an event listener to each similar element, you add it to their common parent. When an event occurs on a child, it bubbles up to the parent, where the handler can determine which child was the actual target.

### Purposes

- To reduce the number of event listeners, improving performance and memory usage.
- To handle events on dynamically added elements without re-attaching listeners.
- To simplify code by centralising event handling logic.

### Syntax Rules and Structure

```js
parentElement.addEventListener("eventType", (event) => {
  const target = event.target.closest("selector");
  if (target) {
    // Handle the event for the matched element
  }
});
```

### Annotated Code Example

```html
<ul id="list">
  <li>Item 1</li>
  <li>Item 2</li>
  <li>Item 3</li>
</ul>
```
```js
// Attach a single listener to the parent <ul>.
document.getElementById("list").addEventListener("click", (event) => {
  const li = event.target.closest("li");
  if (li) {
    console.log("Clicked:", li.textContent);
  }
});
```
**Expected Output (on clicking any `<li>`):**
```
Clicked: Item 2  (for example)
```

## Event Bubbling and Capturing

### Event Bubbling

**Definition:** Event bubbling is the default propagation mode where an event bubbles up from the target element through its ancestors.

**Technical Definition:** Per MDN, when an event is triggered on an element nested inside another element, the event is first triggered on the innermost element, then on its parent, then on its grandparent, and so on up to the `Window`.

**Example:**
```html
<div id="container">
  <button>Click me!</button>
</div>
```
```js
document.body.addEventListener("click", (e) => console.log("Body"));
document.getElementById("container").addEventListener("click", (e) => console.log("Container"));
document.querySelector("button").addEventListener("click", (e) => console.log("Button"));
```
**Expected Output (on clicking the button):**
```
Button
Container
Body
```

### Event Capturing

**Definition:** Event capturing is the reverse of bubbling: the event is triggered on the outermost element first, then on progressively more nested elements until it reaches the target.

**Technical Definition:** Per MDN, capturing works in the opposite order to bubbling: the event is first triggered on the least nested element and then on progressively more nested elements until it reaches the target element. To enable capturing, pass `true` (or `{ capture: true }`) as the third argument to `addEventListener()`.

**Example:**
```js
document.body.addEventListener("click", () => console.log("Body capture"), true);
document.getElementById("container").addEventListener("click", () => console.log("Container capture"), true);
document.querySelector("button").addEventListener("click", () => console.log("Button capture"), true);
```
**Expected Output (on clicking the button):**
```
Body capture
Container capture
Button capture
```

## Passive Listeners

### Definitions

**Core Definition:** A passive listener is an event listener that promises never to call `preventDefault()`, allowing the browser to optimise scrolling performance.

**Technical Definition:** Per Chrome for Developers, passive event listeners solve the problem of scroll-blocking by letting you set a flag in the `options` parameter of `addEventListener` indicating that the listener will never cancel scrolling. When `passive` is `true`, the browser does not need to wait for the listener to execute before scrolling.

**Syntax Rules and Structure:**
```js
element.addEventListener("scroll", handler, { passive: true });
element.addEventListener("touchstart", handler, { passive: true });
```

**When to Use:** Use passive listeners for scroll, touchstart, touchmove, wheel, and other events where `preventDefault()` is not needed.

## Once Listeners

### Definitions

**Core Definition:** A once listener is an event listener that is automatically removed after its first invocation.

**Technical Definition:** Per MDN, the `once` option in `addEventListener()` is a boolean indicating that the listener should be invoked at most once after being added. If `true`, the listener is automatically removed when it is invoked.

**Syntax Rules and Structure:**
```js
element.addEventListener("click", handler, { once: true });
```

**Annotated Code Example:**
```js
const button = document.querySelector("button");
button.addEventListener("click", () => {
  console.log("This runs only once");
}, { once: true });
// Subsequent clicks do nothing.
```

## Custom Events

### Definitions

**Core Definition:** A custom event is an event created by the developer (rather than by the browser) to communicate between different parts of an application.

**Technical Definition:** Per MDN, the `CustomEvent` interface represents events initialized by an application for any purpose. The `CustomEvent()` constructor creates a new `CustomEvent` object. The `detail` property returns any data passed when the event was initialized.

### Purposes

- To create application-specific events for component communication.
- To pass custom data along with events.
- To implement event-driven architectures within a single page or component tree.

### Syntax Rules and Structure

```js
const event = new CustomEvent(type, options);
```

**Component Breakdown:**
- `type`: A string providing the name of the event. Event names are case-sensitive.
- `options` (optional): An object that, in addition to the properties defined in `Event()`, can contain a `detail` property with an event-dependent value associated with the event. This value is accessible via the `CustomEvent.detail` property. Defaults to `null`.

### Annotated Code Example

```js
// Step 1: Create a custom event.
const catFound = new CustomEvent("animalfound", {
  detail: { name: "cat" }
});

// Step 2: Attach a listener.
const element = document.querySelector("body");
element.addEventListener("animalfound", (event) => {
  console.log(event.detail.name); // "cat"
});

// Step 3: Dispatch the event.
element.dispatchEvent(catFound);
```
**Expected Output:**
```
cat
```

## Event Performance

### Definitions

**Core Definition:** Event performance refers to the efficiency with which event listeners are registered, invoked, and managed, particularly in applications with many interactive elements.

**Technical Definition:** Event performance is influenced by the number of listeners, the complexity of handlers, the use of delegation, and the choice of listener options (passive, once). Attaching hundreds of individual listeners is resource-intensive and can degrade performance.

### Best Practices

| Practice | Description |
|----------|-------------|
| **Use event delegation** | Attach a single listener to a parent instead of many listeners to children |
| **Use passive listeners** | Add `{ passive: true }` for scroll and touch events to improve scrolling performance |
| **Avoid DOM operations in handlers** | DOM operations trigger reflows and repaints; batch them or defer them |
| **Use throttling and debouncing** | For high-frequency events (scroll, resize, input), use throttle or debounce to limit handler calls |
| **Remove unused listeners** | Use `removeEventListener()` to prevent memory leaks |
| **Choose the right parent** | In event delegation, select the nearest common parent to minimise the number of events handled |
| **Use `once` for one-time handlers** | Avoids the need for manual removal |


### Real-World Cases

- **Search autocomplete:** Debouncing `input` events to avoid firing an API call on every keystroke.
- **Infinite scroll:** Throttling the `scroll` event to check if the user has reached the bottom of the page.
- **Large lists:** Using event delegation on a `<ul>` to handle clicks on hundreds of `<li>` elements.
- **Drag and drop:** Handling `dragstart`, `dragover`, and `drop` events for file uploads.

## Event Best Practices

### Definitions

**Core Definition:** Event best practices are guidelines for writing clean, performant, and maintainable event-driven code.

### Key Practices

**1. Use Event Delegation for Lists and Repeated Elements**

```js
// GOOD: One listener on the parent.
document.getElementById("list").addEventListener("click", (e) => {
  const li = e.target.closest("li");
  if (li) handleItemClick(li);
});

// BAD: A listener on every <li>.
document.querySelectorAll("li").forEach((li) => {
  li.addEventListener("click", () => handleItemClick(li));
});
```

**2. Use Passive Listeners for Scroll and Touch Events**

```js
window.addEventListener("scroll", onScroll, { passive: true });
window.addEventListener("touchmove", onTouchMove, { passive: true });
```

**3. Use `once: true` for One-Time Handlers**

```js
button.addEventListener("click", () => {
  console.log("This runs only once");
}, { once: true });
```

**4. Remove Listeners When No Longer Needed**

```js
function setup() {
  const handler = () => console.log("Handled");
  element.addEventListener("click", handler);
  return () => element.removeEventListener("click", handler);
}
const cleanup = setup();
// Later:
cleanup();
```

**5. Use `closest()` in Event Delegation**

```js
parent.addEventListener("click", (e) => {
  const button = e.target.closest("button[data-action]");
  if (button) {
    handleAction(button.dataset.action);
  }
});
```

**6. Throttle or Debounce High-Frequency Events**

```js
function debounce(fn, delay) {
  let timer;
  return (...args) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
}

window.addEventListener("resize", debounce(() => {
  console.log("Resized");
}, 200));
```

**7. Avoid Inline Event Handlers**

```html
<!-- BAD: Inline handler -->
<button onclick="handleClick()">Click</button>

<!-- GOOD: addEventListener -->
<button id="btn">Click</button>
<script>
  document.getElementById("btn").addEventListener("click", handleClick);
</script>
```

**8. Understand `this` in Handlers**

```js
// 'this' refers to the element the listener is attached to.
element.addEventListener("click", function() {
  console.log(this); // The element
});

// Arrow functions do not have their own 'this'.
element.addEventListener("click", () => {
  console.log(this); // The enclosing scope's 'this'
});
```
