# CSS 2D Transforms — Comprehensive Cheat Sheet Research

---

## Topic Overview

### Definitions

**Core Definition:** CSS 2D Transforms is a CSS module that allows elements styled with CSS to be transformed in two-dimensional space, enabling rotation, scaling, skewing, and translation of elements without affecting the surrounding document layout.

**Technical Definition:** The `transform` CSS property lets you rotate, scale, skew, or translate an element by modifying the coordinate space of the CSS visual formatting model. If the property has a value different from `none`, a stacking context is created, and the element acts as a containing block for any `position: fixed` or `position: absolute` descendants. The module defines a set of CSS properties that affect the visual rendering of elements to which those properties are applied; these effects are applied after elements have been sized and positioned according to the visual formatting model from CSS2. Transforms operate by modifying the coordinate system within each element, where positions and sizes can be thought of as being expressed in pixels, starting from an origin point with positive values proceeding to the right and down.

**Beginner-Friendly Explanation:** Imagine you have a photograph on a table. You can slide it around (translate), make it bigger or smaller (scale), spin it (rotate), or tilt it at an angle (skew) — all without moving the other objects on the table. CSS 2D transforms do the same thing to elements on a webpage. The element still occupies its original space in the document flow, but its visual appearance changes. This makes transforms perfect for animations and hover effects because the browser does not have to recalculate the positions of other elements on the page.

---

### Key Characteristics

| Characteristic | Description |
|---|---|
| **Visual only** | Transforms change appearance without affecting document layout. |
| **Stacking context** | A non-`none` transform creates a stacking context and containing block. |
| **Composable** | Multiple transform functions can be chained in one declaration. |
| **Order-dependent** | The sequence of transform functions matters greatly. |
| **Transform-origin** | The point around which transforms are applied is configurable. |
| **Individual properties** | `translate`, `rotate`, and `scale` can be set independently. |
| **Matrix form** | All 2D transforms can be expressed as a single `matrix()` function. |
| **Performance-friendly** | Transforms are handled by the rendering engine more efficiently than layout-based changes. |

## 1. The Transform Functions: `translate()`, `scale()`, `rotate()`, and `skew()`

### Definitions

**Core Definition:** Transform functions are individual CSS functions that each perform a specific type of 2D transformation — translation (movement), scaling (resizing), rotation (spinning), or skewing (tilting) — on an element.

**Technical Definition:** The `transform` property may be specified as either the keyword value `none` or as one or more `<transform-function>` values. The primary 2D transform functions are: `translate()` for moving an element, `scale()` for resizing, `rotate()` for rotation, and `skew()` for skewing. Each function also has axis-specific variants: `translateX()`, `translateY()`, `scaleX()`, `scaleY()`, `skewX()`, and `skewY()`. The functions are combined from left to right, with each function establishing a new coordinate space for the next function.

**Beginner-Friendly Explanation:** Each transform function is a specific action you can apply to an element. `translate(50px, 20px)` slides it 50 pixels right and 20 pixels down. `scale(2)` makes it twice as big. `rotate(45deg)` spins it 45 degrees clockwise. `skew(10deg, 5deg)` tilts it diagonally. You can chain multiple functions together in one `transform` declaration, and the browser applies them in sequence.

---

### Purposes

- To move elements visually without affecting layout (`translate`).
- To resize elements for emphasis or animation (`scale`).
- To rotate elements for visual effects or loading indicators (`rotate`).
- To create angled or diagonal visual treatments (`skew`).
- To combine multiple transformations in a single declaration.

---

### Syntax Rules and Structure

#### Complete General Syntax

```css
selector {
    transform: none;
    transform: <transform-function>+;
}

/* Individual function syntax */
transform: translate(<length-percentage> [, <length-percentage>]?);
transform: translateX(<length-percentage>);
transform: translateY(<length-percentage>);
transform: scale(<number> [, <number>]?);
transform: scaleX(<number>);
transform: scaleY(<number>);
transform: rotate(<angle>);
transform: skew(<angle> [, <angle>]?);
transform: skewX(<angle>);
transform: skewY(<angle>);
```

#### Component Breakdown

| Function | Parameter Type | Description |
|---|---|---|
| `translate(x, y)` | `<length-percentage>` | Moves the element along the X and Y axes. |
| `translateX(x)` | `<length-percentage>` | Moves the element along the X axis only. |
| `translateY(y)` | `<length-percentage>` | Moves the element along the Y axis only. |
| `scale(x, y)` | `<number>` | Scales the element along both axes; uniform if one value. |
| `scaleX(x)` | `<number>` | Scales along the X axis only. |
| `scaleY(y)` | `<number>` | Scales along the Y axis only. |
| `rotate(a)` | `<angle>` | Rotates the element clockwise. |
| `skew(x, y)` | `<angle>` | Skews the element along both axes. |
| `skewX(x)` | `<angle>` | Skews along the X axis only. |
| `skewY(y)` | `<angle>` | Skews along the Y axis only. |

#### Syntax Rules

1. `transform` accepts the keyword `none` or one or more space-separated `<transform-function>` values.
2. Multiple functions are combined from left to right — each establishes a new coordinate space for the next.
3. The visual result matches the written order of functions when keeping the parent coordinate space fixed.
4. `translate()` percentages refer to the size of the element's border box.
5. `scale()` with one value applies uniformly to both axes.
6. `rotate()` accepts degrees (`deg`), gradians (`grad`), radians (`rad`), or turns (`turn`).
7. Negative values are allowed for `translate` and `rotate`; `scale` with negative values flips the element.

#### Constraints and Limitations

- **Only transformable elements** — non-replaced inline boxes, table-column boxes, and table-column-group boxes cannot be transformed.
- **Percentage translation** — percentages for `translate` refer to the element's own border box size, not the parent's.
- **No layout impact** — transforms do not change the document flow or trigger layout recalculations.
- **Accessibility** — scaling and zooming animations can trigger migraines; respect `prefers-reduced-motion`.

## 2. Individual Transform Properties: `translate`, `scale`, and `rotate`

### Definitions

**Core Definition:** The individual transform properties (`translate`, `rotate`, and `scale`) allow authors to specify simple transforms independently, without using the `transform` shorthand and without needing to repeat other transform functions when changing just one.

**Technical Definition:** The `translate`, `rotate`, and `scale` properties allow authors to specify simple transforms independently. They are defined in the CSS Transforms Module Level 2 and are applied in a fixed order: first `translate` (outermost), then `rotate`, and finally `scale` (innermost). This order is fixed regardless of the order in which the properties are declared in CSS. If one of the individual transform properties is declared alongside the `transform` property, the individual transforms are applied first, and the `transform` functions are applied last (innermost).

**Beginner-Friendly Explanation:** Before individual transform properties, if you wanted to change just the scale on hover, you had to rewrite the entire `transform` declaration, including the translate and rotate values. With `translate`, `rotate`, and `scale`, you can set each one independently. The browser always applies them in the same order: translate first, then rotate, then scale. This makes animations much simpler because you can animate each property separately.

---

### Purposes

- To simplify animations by allowing each transform component to be animated independently.
- To avoid repeating unchanged transform functions when modifying a single transform.
- To provide a more intuitive API for common transform operations.
- To enable independent transitions on translate, rotate, and scale.
- To work alongside the `transform` property without conflict.

---

### Syntax Rules and Structure

#### Complete General Syntax

```css
selector {
    translate: <length-percentage> [<length-percentage>]?;
    rotate: <angle>;
    scale: <number> [<number>]?;
}
```

#### Component Breakdown

| Property | Accepted Values | Description |
|---|---|---|
| `translate` | One or two `<length-percentage>` values | X and optional Y translation. |
| `rotate` | One `<angle>` value | Clockwise rotation. |
| `scale` | One or two `<number>` values | X and optional Y scale factor. |

#### Syntax Rules

1. The individual transform properties are applied in a fixed order: `translate` (outermost), then `rotate`, then `scale` (innermost).
2. This order is independent of the declaration order in CSS.
3. If used alongside `transform`, the individual properties are applied first, and `transform` is applied last (innermost).
4. The `translate` property accepts one or two values; `scale` accepts one or two values.
5. The `rotate` property accepts a single `<angle>` value.
6. These properties share the same `transform-origin` as the `transform` property.
7. They cascade normally by specificity, unlike the order-dependent functions within a single `transform` declaration.

#### Constraints and Limitations

- **Only `translate`, `rotate`, and `scale` exist as individual properties** — `skewX`, `skewY`, `translateX`, `translateY`, `scaleX`, and `scaleY` do not have individual property equivalents.
- **Fixed order** — the application order cannot be changed; translate always happens before rotate, and rotate before scale.
- **Browser support** — supported in Chrome 104+, Firefox 72+, and Safari 14.1+.
- **No `skew` property** — skew must still be applied via the `transform` property.

- **Interactive cards:** Using `scale` for hover effects while maintaining a `translate` offset.
- **Simplified CSS:** Reducing repetition in stylesheets that use transforms extensively.

## 3. Transform Origin: `transform-origin`

### Definitions

**Core Definition:** The `transform-origin` property sets the point around which an element's transforms are applied. By default, this is the centre of the element (50% 50%).

**Technical Definition:** The `transform-origin` property is used in conjunction with CSS transforms, letting you change the point of origin of a transform. For 2D transforms, it takes up to two space-separated keyword or length values: the first for the horizontal position and the second for the vertical position. Values can be lengths, percentages, or the keywords `top`, `left`, `right`, `bottom`, and `center`. Percentage and length values represent an offset of the transform-origin from the top-left corner of the element's border box.

**Beginner-Friendly Explanation:** The `transform-origin` determines the "pivot point" for your transforms. If you rotate a box, does it spin around its centre, its top-left corner, or some other point? By default, it spins around the centre (50% 50%). If you set `transform-origin: top left`, the rotation happens around the top-left corner, which makes the element swing like a door hinge. This is crucial for creating specific visual effects.

---

### Purposes

- To control the pivot point for rotation, scaling, and skewing.
- To create effects like door-hinge rotations or corner-anchored scaling.
- To align the transform origin with a specific feature of the element.
- To enable precise control over animation behaviour.
- To support percentage and length-based origin positioning.

---

### Syntax Rules and Structure

#### Complete General Syntax

```css
selector {
    transform-origin: <x-offset> <y-offset>;
    /* Keywords */
    transform-origin: left top;
    transform-origin: center center;
    transform-origin: right bottom;
    /* Lengths and percentages */
    transform-origin: 0 0;
    transform-origin: 25% 75%;
    transform-origin: 50px 100px;
    /* Single value (Y defaults to center) */
    transform-origin: top;
    transform-origin: left;
}
```

#### Component Breakdown

| Value Type | Examples | Description |
|---|---|---|
| Keyword (X) | `left`, `center`, `right` | Horizontal position. |
| Keyword (Y) | `top`, `center`, `bottom` | Vertical position. |
| Percentage | `25% 75%` | Relative to the element's border box. |
| Length | `50px 100px` | Absolute offset from the top-left corner. |

#### Syntax Rules

1. `transform-origin` accepts one or two values for 2D transforms.
2. The first value is the horizontal position; the second is the vertical position.
3. If only one value is given, the second defaults to `center`.
4. Keywords `left`, `center`, and `right` map to `0%`, `50%`, and `100%` for the X axis.
5. Keywords `top`, `center`, and `bottom` map to `0%`, `50%`, and `100%` for the Y axis.
6. Percentages and lengths are relative to the element's border box.
7. Negative values are allowed for percentages and lengths.

#### Constraints and Limitations

- **No effect without transform** — `transform-origin` has no visible effect unless a `transform` is applied.
- **2D vs. 3D** — the Z-axis origin requires a third value (3D transforms only).
- **Shared origin** — the individual transform properties (`translate`, `rotate`, `scale`) share the same `transform-origin` as the `transform` property.

## 4. The 2D Matrix: `matrix(a, b, c, d, tx, ty)`

### Definitions

**Core Definition:** The `matrix()` CSS function defines a homogeneous 2D transformation matrix that combines all 2D transform functions into a single declaration, allowing precise programmatic control over transformation values.

**Technical Definition:** The `matrix()` function defines a homogeneous 2D transformation matrix. Its result is a `<transform-function>` data type. The `matrix(a, b, c, d, tx, ty)` function is a shorthand for `matrix3d(a, b, 0, 0, c, d, 0, 0, 0, 0, 1, 0, tx, ty, 0, 1)`. It is specified with six values: `a`, `b`, `c`, and `d` are `<number>` values describing the linear transformation, and `tx` and `ty` are `<number>` values describing the translation to apply. The values represent the functions `matrix(scaleX(), skewY(), skewX(), scaleY(), translateX(), translateY())`. The constant values are implied and not passed as parameters; the other parameters are described in the column-major order.

**Beginner-Friendly Explanation:** The `matrix()` function is the most powerful but least readable transform function. It combines all other transform functions into six numbers. Think of it as the "assembly language" of CSS transforms. You can express any 2D transformation — translation, rotation, scaling, skewing — as a combination of these six values. It is primarily used when generating CSS from JavaScript or when performing mathematical calculations that need to be converted to CSS.

---

### Purposes

- To combine all 2D transforms into a single matrix representation.
- To enable programmatic generation of transforms from JavaScript.
- To provide a mathematical foundation for understanding transforms.
- To interpolate between complex transform states during animation.
- To express transformations that are difficult to write with individual functions.

---

### Syntax Rules and Structure

#### Complete General Syntax

```css
selector {
    transform: matrix(a, b, c, d, tx, ty);
}
```

#### Component Breakdown

| Parameter | Type | Description | Corresponds To |
|---|---|---|---|
| `a` | `<number>` | Scale X / rotation cosine. | `scaleX()` |
| `b` | `<number>` | Skew Y / rotation sine. | `skewY()` |
| `c` | `<number>` | Skew X / rotation sine. | `skewX()` |
| `d` | `<number>` | Scale Y / rotation cosine. | `scaleY()` |
| `tx` | `<number>` | Translation X. | `translateX()` |
| `ty` | `<number>` | Translation Y. | `translateY()` |

#### The Matrix Equation

The transformation matrix is applied as follows:

```
| a  c  tx |   | x |
| b  d  ty | × | y |
| 0  0  1  |   | 1 |
```

The resulting coordinates are:
- `x' = a × x + c × y + tx`
- `y' = b × x + d × y + ty`

#### Common Matrix Values

| Transform | Matrix |
|---|---|
| Identity (no transform) | `matrix(1, 0, 0, 1, 0, 0)` |
| Translate(50, 20) | `matrix(1, 0, 0, 1, 50, 20)` |
| Scale(2, 2) | `matrix(2, 0, 0, 2, 0, 0)` |
| Rotate(θ) | `matrix(cos θ, sin θ, -sin θ, cos θ, 0, 0)` |
| SkewX(θ) | `matrix(1, 0, tan θ, 1, 0, 0)` |
| SkewY(θ) | `matrix(1, tan θ, 0, 1, 0, 0)` |

#### Syntax Rules

1. `matrix()` accepts exactly six `<number>` values.
2. The values are described in column-major order.
3. The constant values (`0, 0, 1` in the third column) are implied and not passed.
4. `matrix()` can be combined with other transform functions in a chain.
5. The function is equivalent to `matrix3d(a, b, 0, 0, c, d, 0, 0, 0, 0, 1, 0, tx, ty, 0, 1)`.
6. Negative values are allowed for all parameters.

#### Constraints and Limitations

- **Readability** — matrix values are difficult for humans to interpret; the transform shorthand is preferred for manual authoring.
- **No units** — `tx` and `ty` are unitless numbers interpreted as pixels.
- **Programmatic use** — matrices are best generated by JavaScript or mathematical tools.
- **Interpolation** — the browser can interpolate between two matrices for smooth animation.

## 5. Transform Stacking Order

### Definitions

**Core Definition:** Transform stacking order describes how the browser evaluates a chain of transform functions within a single `transform` property. Functions are combined from left to right, with each function establishing a new coordinate space for the next function.

**Technical Definition:** The transform functions are combined from left to right — each function establishes a new coordinate space for the next function — so the visual result matches the written order of the functions. Alternatively, keeping the parent coordinate space fixed, the same transformation can be described as applying the functions in reverse order (right to left). This means that `transform: translate(50px) rotate(45deg)` is not the same as `transform: rotate(45deg) translate(50px)`. The order of functions inside the `transform` property is relevant, but the individual transform properties (`translate`, `rotate`, `scale`) apply in a fixed order regardless of declaration order.

**Beginner-Friendly Explanation:** When you chain multiple transforms, the order matters enormously. Think of it like this: `translate(100px) rotate(45deg)` means "first move 100 pixels right, then rotate 45 degrees around your new position." But `rotate(45deg) translate(100px)` means "first rotate 45 degrees, then move 100 pixels in the direction you are now facing." These produce completely different results. The rule of thumb is: the rightmost function is applied first to the element, and then the functions to its left are applied in sequence.

### Purposes

- To understand why the order of transform functions matters.
- To predict the visual result of a transform chain.
- To debug unexpected transform behaviour caused by function order.
- To choose between the shorthand and individual properties based on ordering needs.
- To write transform chains that produce the intended visual effect.

---

### Syntax Rules and Structure

#### Complete General Syntax

```css
/* Order matters: left-to-right (each establishes a new coordinate space) */
transform: <function1> <function2> <function3>;

/* Visual result: applied in reverse order (right to left) */
/* function3 first, then function2, then function1 */
```

#### Component Breakdown

| Order | Example | Visual Result |
|---|---|---|
| A then B | `translate(50px) rotate(45deg)` | Move right, then rotate around the new position. |
| B then A | `rotate(45deg) translate(50px)` | Rotate, then move in the rotated direction. |

#### Syntax Rules

1. Transform functions are combined from left to right, with each establishing a new coordinate space for the next.
2. The visual result matches the written order when keeping the parent coordinate space fixed.
3. The same transformation can be described as applying functions in reverse order (right to left) with a fixed coordinate space.
4. Changing the order of functions changes the visual result.
5. Individual transform properties (`translate`, `rotate`, `scale`) apply in a **fixed order** regardless of declaration order.
6. When individual properties and `transform` are used together, individual properties are applied first, then `transform`.

#### Constraints and Limitations

- **Order dependency** — the same set of functions in a different order produces a different result.
- **No order control for individual properties** — translate always applies before rotate, which always applies before scale.
- **Debugging difficulty** — order-dependent behaviour can be confusing; always test the visual result.
