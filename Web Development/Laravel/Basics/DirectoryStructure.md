# Modern Directory Structure & Framework Assets

Laravel's directory structure is a deliberate expression of its convention-over-configuration philosophy. Every directory has a purpose, and understanding where things belong is the first step to working idiomatically with the framework. Laravel 11 introduced significant simplifications to this structure, reducing the number of files developers must navigate while preserving clarity.

---

## 1. Root Application Directories

### 1.1 `app/` — Core Application Logic

The `app/` directory contains the **core code of your application**. Almost all of your application's classes live here. It is autoloaded by Composer using PSR-4 conventions under the `App\` namespace.

**Default structure:**

```
app/
├── Http/
│   ├── Controllers/       # Request handlers
│   ├── Middleware/        # Request/response filters
│   └── Requests/          # Form request validation (if created)
├── Models/                # Eloquent models
├── Providers/             # Service providers
└── ...
```

| Subdirectory | Purpose |
|-------------|---------|
| **`Http/Controllers/`** | Controllers handle incoming requests and return responses. In Laravel 11+, the base `Controller` class is minimal — controllers extend a simple abstract class or none at all. |
| **`Http/Middleware/`** | Middleware filters HTTP requests entering the application (auth, rate limiting, CORS). |
| **`Http/Requests/`** | Form request classes encapsulate validation logic. Not created by default; generate with `php artisan make:request`. |
| **`Models/`** | Eloquent models representing database tables. Laravel 11+ includes a `User` model by default. |
| **`Providers/`** | Service providers bootstrap application services. Laravel 11+ includes only `AppServiceProvider` by default. |

**What changed in Laravel 11:**

The `app/` directory was **significantly slimmed down**. The following were removed from the default skeleton:

| Removed | Reason |
|---------|--------|
| `app/Console/Kernel.php` | Consolidated into `bootstrap/app.php` |
| `app/Http/Kernel.php` | Consolidated into `bootstrap/app.php` |
| `app/Exceptions/Handler.php` | Consolidated into `bootstrap/app.php` |
| `app/Http/Middleware/*` (9 middlewares) | Moved into the framework; only custom middleware remains |
| `app/Providers/RouteServiceProvider.php` | Routing configured in `bootstrap/app.php` |
| `app/Providers/EventServiceProvider.php` | Event discovery is automatic |
| `app/Providers/BroadcastServiceProvider.php` | Broadcasting configured via `install:broadcasting` |
| `app/Providers/AuthServiceProvider.php` | Policies auto-discovered |

This was not an arbitrary reduction — it reflected **years of observation** about which files developers actually modified. The nine middlewares, for example, were almost never customized, yet they cluttered the directory and confused newcomers.

**Domain-driven structure (optional):** For larger applications, you can restructure `app/` by domain rather than by technical layer:

```
app/
├── Billing/
│   ├── Models/
│   ├── Actions/
│   ├── Services/
│   └── Http/
├── Catalog/
│   ├── Models/
│   ├── Actions/
│   └── Http/
```

Laravel does not enforce this, but the framework's autoloading and container resolution support it seamlessly.

### 1.2 `bootstrap/` — Framework Optimization & App Configuration

The `bootstrap/` directory contains the files that **bootstrap the framework** and store **generated optimization caches**.

```
bootstrap/
├── app.php                # Application configuration (Laravel 11+)
├── providers.php          # Service provider registration
└── cache/                 # Generated optimization files
    ├── config.php         # Cached configuration
    ├── events.php         # Cached event listeners
    ├── packages.php       # Cached package manifests
    ├── routes-v7.php      # Cached routes
    └── services.php       # Cached services
```

**`bootstrap/app.php`** — The single most important configuration file in Laravel 11+. It replaces the HTTP kernel, Console kernel, and exception handler. It configures:

- Routing (web, API, console, health check)
- Middleware (global, web group, API group, aliases)
- Exceptions (reporting, rendering, throttling)
- Service providers (via `providers.php`)
- Application paths and base directory

**`bootstrap/providers.php`** — Lists the service providers your application registers. In Laravel 10 and earlier, this was inside `config/app.php`. Laravel 11 moved it here to keep provider registration separate from general configuration.

**`bootstrap/cache/`** — Contains framework-generated optimization files. This directory **should be writable** by the web server. Files are generated by `php artisan optimize` and related commands. The `.gitignore` inside this directory excludes all generated files except `.gitignore` itself.

### 1.3 `config/` — Configuration Files

The `config/` directory holds **all of your application's configuration files**. Every file returns a PHP array, and values are accessed via the `config()` helper using dot notation.

**Default files (Laravel 11+):**

| File | Purpose |
|------|---------|
| `app.php` | Application name, environment, debug mode, providers, aliases |
| `auth.php` | Authentication guards, providers, password reset |
| `cache.php` | Cache stores and drivers |
| `database.php` | Database connections (SQLite, MySQL, PostgreSQL, SQL Server) |
| `filesystems.php` | Disk configurations (local, public, S3) |
| `logging.php` | Log channels and handlers |
| `mail.php` | Mailers and transports |
| `queue.php` | Queue connections and failed job storage |
| `services.php` | Third-party service credentials (Stripe, Mailgun, etc.) |
| `session.php` | Session drivers, lifetime, encryption |

**Published on-demand:** Laravel 11 **removed several config files** from the default installation. These are now published only when needed:

| File | Published By |
|------|-------------|
| `config/broadcasting.php` | `php artisan install:broadcasting` |
| `config/cors.php` | `php artisan config:publish cors` |
| `config/hashing.php` | `php artisan config:publish hashing` |
| `config/sanctum.php` | `php artisan install:api` |
| `config/view.php` | `php artisan config:publish view` |

**Why this matters:** In Laravel 10 and earlier, a fresh install shipped with ~20 config files. Most were never modified. Laravel 11 ships with ~10, and the framework falls back to sensible defaults for the missing ones. When you need to customize a published config file, run its publish command.

**Caching:** All config files are compiled into a single `bootstrap/cache/config.php` file by `php artisan config:cache`. After caching, `env()` calls outside config files return `null` — this is the single most important rule to remember.

### 1.4 `database/` — Migrations, Factories, Seeders

The `database/` directory contains **database-related assets**: schema migrations, model factories, and seeders. It also holds the default **SQLite database file** in Laravel 11+.

```
database/
├── factories/             # Model factories for testing/seeding
│   └── UserFactory.php
├── migrations/            # Schema migrations
│   ├── 0001_01_01_000000_create_users_table.php
│   ├── 0001_01_01_000001_create_cache_table.php
│   └── 0001_01_01_000002_create_jobs_table.php
├── seeders/               # Database seeders
│   └── DatabaseSeeder.php
└── database.sqlite        # Default SQLite database (created on first migration)
```

| Subdirectory | Purpose |
|-------------|---------|
| **`migrations/`** | Version-controlled schema changes. Each migration has an `up()` and `down()` method. |
| **`factories/`** | Generate fake model instances for testing and seeding. |
| **`seeders/`** | Populate the database with test or initial data. |

**Default migrations in Laravel 11+:**

Laravel 11 ships with **three** default migrations (down from five in Laravel 10):

1. `create_users_table` — Users, password reset tokens, sessions
2. `create_cache_table` — Cache and cache locks
3. `create_jobs_table` — Jobs, job batches, failed jobs

**SQLite default:** The default `DB_CONNECTION` is now `sqlite`. Running `php artisan migrate` creates `database/database.sqlite` automatically if it doesn't exist. This makes Laravel immediately usable without a database server.

**Commands:**
```bash
php artisan make:migration create_posts_table
php artisan make:factory PostFactory
php artisan make:seeder PostSeeder
php artisan migrate
php artisan db:seed
```

### 1.5 `public/` — Entry Point & Compiled Assets

The `public/` directory is the **document root** of your application. It contains the entry point and publicly accessible assets.

```
public/
├── index.php              # The single entry point for all requests
├── .htaccess              # Apache rewrite rules
├── favicon.ico
├── robots.txt
└── build/                 # Compiled assets (Vite output)
    ├── assets/
    │   ├── app-abc123.js
    │   └── app-def456.css
    └── manifest.json
```

**`index.php`** — All requests enter the application through this file. It is deliberately minimal: it loads the Composer autoloader, retrieves the application instance from `bootstrap/app.php`, and dispatches the request to the kernel. The web server must be configured to point its document root at `public/`, never the project root.

**`build/`** — Vite compiles frontend assets into this directory. The `manifest.json` maps source files to hashed filenames, enabling cache-busting. This directory is in `.gitignore` — it is generated during deployment via `npm run build`.

**Security note:** Never place sensitive files (`.env`, `composer.json`, `storage/`) inside `public/`. Point the document root at `public/` and everything else is protected by the directory structure.

### 1.6 `resources/` — Uncompiled Frontend Assets

The `resources/` directory contains **uncompiled frontend assets**: Blade templates, raw CSS/JS, and translation files.

```
resources/
├── css/
│   └── app.css            # Tailwind CSS entry point
├── js/
│   ├── app.js             # JavaScript entry point
│   └── bootstrap.js       # Axios/libraries setup
├── views/
│   ├── welcome.blade.php
│   └── components/        # Blade components
└── lang/                  # Translation files (Laravel 11+)
    └── en/
        └── validation.php
```

| Subdirectory | Purpose |
|-------------|---------|
| **`views/`** | Blade templates. Compiled to `storage/framework/views/`. |
| **`css/`** | Raw CSS/Tailwind source files. Compiled by Vite. |
| **`js/`** | Raw JavaScript source files. Compiled by Vite. |
| **`lang/`** | Localization files. In Laravel 10 and earlier, this was at the project root (`lang/`). Laravel 11 moved it under `resources/`. |

**Blade views:** Blade is Laravel's templating engine. Views use `.blade.php` extension and support template inheritance (`@extends`, `@section`), components (`<x-alert>`), and directives (`@if`, `@foreach`, `@auth`).

**Compilation:** Blade views are compiled to plain PHP on first access and cached in `storage/framework/views/`. The cache is invalidated when the source `.blade.php` file is modified.

### 1.7 `routes/` — Routing Files

The `routes/` directory contains **all route definitions** for your application.

```
routes/
├── web.php                # Web routes (session, CSRF, cookies)
├── console.php            # Console commands and scheduling
├── api.php                # API routes (created via install:api)
└── channels.php           # Broadcast channels (created via install:broadcasting)
```

| File | Middleware Group | Purpose |
|------|-----------------|---------|
| **`web.php`** | `web` | Browser-facing routes with session, CSRF, and cookie handling |
| **`api.php`** | `api` | Stateless API routes with rate limiting; no session/CSRF |
| **`console.php`** | — | Closure-based Artisan commands and scheduled tasks |
| **`channels.php`** | — | Broadcast channel authorization |

**Laravel 11 changes:** Only `web.php` and `console.php` are present by default. `api.php` is created by `php artisan install:api` (which also installs Sanctum). `channels.php` is created by `php artisan install:broadcasting`.

**Route registration:** Routes are registered in `bootstrap/app.php` via `withRouting()`:

```php
->withRouting(
    web: __DIR__.'/../routes/web.php',
    api: __DIR__.'/../routes/api.php',
    commands: __DIR__.'/../routes/console.php',
    channels: __DIR__.'/../routes/channels.php',
    health: '/up',
)
```

**Route caching:** In production, `php artisan route:cache` compiles all routes into a single file for faster registration. This requires all routes to be controller-based (closure routes cannot be cached).

### 1.8 `storage/` — Logs, Uploads, Caches

The `storage/` directory contains **application-generated files**: logs, user uploads, compiled templates, and framework caches.

```
storage/
├── app/
│   ├── public/            # User-uploaded files (public disk)
│   └── private/           # Private files (local disk)
├── framework/
│   ├── cache/             # Framework cache files
│   ├── sessions/          # File-based sessions
│   └── views/             # Compiled Blade templates
└── logs/
    └── laravel.log        # Application logs
```

| Subdirectory | Purpose | Writable? |
|-------------|---------|-----------|
| **`app/public/`** | User uploads accessible via `storage:link` | Yes |
| **`app/private/`** | Private files not web-accessible | Yes |
| **`framework/cache/`** | File-based cache storage | Yes |
| **`framework/sessions/`** | File-based session storage | Yes |
| **`framework/views/`** | Compiled Blade templates | Yes |
| **`logs/`** | Application logs (`laravel.log`) | Yes |

**The storage symlink:** The `public/storage` symlink points to `storage/app/public`. Create it with:

```bash
php artisan storage:link
```

This allows user uploads stored in `storage/app/public/` to be served directly by the web server (e.g., `https://example.com/storage/avatars/user.jpg`).

**Permissions:** The `storage/` and `bootstrap/cache/` directories must be writable by the web server. In production, this typically means `www-data` or `nginx` ownership:

```bash
sudo chown -R www-data:www-data storage bootstrap/cache
sudo chmod -R 775 storage bootstrap/cache
```

**Log channels:** Laravel's logging is configured in `config/logging.php`. The default `stack` channel writes to `storage/logs/laravel.log`. In production, consider `daily` (rotating logs) or external services (Papertrail, Sentry).

### 1.9 `tests/` — Feature & Unit Testing

The `tests/` directory contains **automated tests**. Laravel ships with PHPUnit by default, though **Pest** is increasingly the community preference.

```
tests/
├── Feature/               # Integration tests (full HTTP stack)
│   └── ExampleTest.php
├── Unit/                  # Isolated unit tests
│   └── ExampleTest.php
├── Pest.php               # Pest configuration (if using Pest)
├── TestCase.php           # Base test case
└── CreatesApplication.php # Application bootstrap for tests
```

| Directory | Purpose |
|-----------|---------|
| **`Feature/`** | Tests that boot the full application and make HTTP requests. Slower but more realistic. |
| **`Unit/`** | Tests that isolate a single class or method. Faster but less comprehensive. |

**Pest vs. PHPUnit:** Pest is a testing framework built on top of PHPUnit that provides a more expressive, readable syntax. It is the default in Laravel 12 starter kits. PHPUnit remains the underlying engine — Pest is a wrapper.

**Running tests:**
```bash
php artisan test
php artisan test --filter=UserTest
./vendor/bin/pest
./vendor/bin/phpunit
```

**Testing environment:** Tests use `.env.testing` if present, overriding `.env`. The default `phpunit.xml` sets `APP_ENV=testing` and `DB_CONNECTION=sqlite` with an in-memory database for speed.

### 1.10 `vendor/` — Third-Party Dependencies

The `vendor/` directory contains **all Composer-installed dependencies**, including the Laravel framework itself, Symfony components, and third-party packages.

**Key points:**
- **Never committed to version control.** It is in `.gitignore`.
- **Generated by `composer install`** on deployment.
- **Generated by `composer update`** locally to upgrade dependencies.
- **Autoloaded via `vendor/autoload.php`**, required by `public/index.php`.

**Production installation:**
```bash
composer install --no-dev --prefer-dist --optimize-autoloader
```

| Flag | Purpose |
|------|---------|
| `--no-dev` | Exclude development dependencies (PHPUnit, Faker, etc.) |
| `--prefer-dist` | Use distribution archives (faster than source) |
| `--optimize-autoloader` | Generate a classmap for faster autoloading |

**Composer files:**
- `composer.json` — Declares dependencies and scripts (committed)
- `composer.lock` — Locks exact versions (committed)
- `vendor/` — Installed packages (not committed)

## 2. Root Files & CLI Entrypoints

### 2.1 `.env` and `.env.example`

| File | Committed? | Purpose |
|------|-----------|---------|
| **`.env`** | No | Your actual environment values (secrets, credentials) |
| **`.env.example`** | Yes | Template with placeholder values; documents required variables |

**Workflow:**
```bash
cp .env.example .env
php artisan key:generate
```

**Key rules:**
- Never commit `.env` — it contains secrets.
- Always commit `.env.example` — it documents required variables.
- All `.env` values are strings; use reserved values (`true`, `false`, `null`, `empty`) for type casting.
- After `php artisan config:cache`, `env()` outside config files returns `null`.

**Environment-specific files:**
- `.env.testing` — Overrides `.env` during tests
- `.env.local` — Used by some deployment workflows
- `.env.production` — Not loaded automatically; injected via deployment

### 2.2 `artisan` — The CLI Entrypoint

The `artisan` file is the **command-line interface** for Laravel. It is a PHP script that bootstraps the application in console mode and dispatches commands.

**Common commands:**

| Category | Command | Purpose |
|----------|---------|---------|
| **Scaffolding** | `make:model`, `make:controller`, `make:migration` | Generate boilerplate |
| **Database** | `migrate`, `db:seed`, `migrate:fresh` | Manage schema and data |
| **Optimization** | `optimize`, `config:cache`, `route:cache` | Compile caches |
| **Development** | `serve`, `tinker`, `queue:work` | Local development |
| **Maintenance** | `down`, `up`, `key:generate` | Application state |

**Custom commands:** Create with `php artisan make:command SendEmails`. Registered automatically in Laravel 11+ (the `Commands` directory is scanned).

**Scheduling:** Define scheduled tasks in `routes/console.php` using the `Schedule` facade:

```php
use Illuminate\Support\Facades\Schedule;

Schedule::command('emails:send')->daily();
Schedule::command('queue:work --stop-when-empty')->everyMinute();
```

**Tinker:** `php artisan tinker` opens an interactive REPL for the application. Useful for testing queries, dispatching jobs, and inspecting the container.

### 2.3 `vite.config.js` — Frontend Asset Compilation

**Vite** is Laravel's default frontend build tool. It replaces Laravel Mix (webpack-based) and provides **blazing-fast hot module replacement (HMR)** during development.

**Default `vite.config.js`:**
```javascript
import { defineConfig } from 'vite';
import laravel from 'laravel-vite-plugin';
import tailwindcss from '@tailwindcss/vite';

export default defineConfig({
    plugins: [
        laravel({
            input: ['resources/css/app.css', 'resources/js/app.js'],
            refresh: true,
        }),
        tailwindcss(),
    ],
});
```

**Key concepts:**

| Concept | Description |
|---------|-------------|
| **`input`** | Entry points Vite compiles (CSS, JS) |
| **`refresh`** | Blade files that trigger full page reloads on change |
| **HMR** | Hot Module Replacement — JS/CSS updates without page reload |
| **`@vite` directive** | Blade directive that injects the correct asset URLs |

**Development vs. production:**

```bash
# Development (HMR, no minification)
npm run dev

# Production (minified, hashed, optimized)
npm run build
```

**In Blade templates:**
```blade
@vite(['resources/css/app.css', 'resources/js/app.js'])
```

In development, this points to the Vite dev server (`http://localhost:5173`). In production, it reads `public/build/manifest.json` and generates hashed URLs.

**The hot file:** When `npm run dev` runs, Vite writes a `public/hot` file. Laravel's `@vite` directive checks for this file to determine whether to use the dev server or the built assets. The file is removed when the dev server stops.

**Tailwind CSS:** Laravel 11+ uses Tailwind CSS v4, which is configured via the `@tailwindcss/vite` plugin rather than a `tailwind.config.js` file. The `resources/css/app.css` file contains `@import "tailwindcss";`.

## Summary: What Changed in Laravel 11+

| Aspect | Laravel 10 | Laravel 11+ |
|--------|-----------|-------------|
| **HTTP Kernel** | `app/Http/Kernel.php` | `bootstrap/app.php` |
| **Console Kernel** | `app/Console/Kernel.php` | `bootstrap/app.php` |
| **Exception Handler** | `app/Exceptions/Handler.php` | `bootstrap/app.php` |
| **Service Providers** | 5 default providers | 1 default provider (`AppServiceProvider`) |
| **Config Files** | ~20 shipped | ~10 shipped; others published on demand |
| **Default DB** | MySQL | SQLite |
| **`lang/` directory** | Project root | `resources/lang/` (moved under `resources/`) |
| **`api.php` routes** | Shipped by default | Created via `install:api` |
| **`channels.php` routes** | Shipped by default | Created via `install:broadcasting` |
| **Default migrations** | 5 | 3 |
| **Middleware** | 9 in `app/Http/Middleware/` | Moved into framework |

## Key Takeaways

1. **`app/` holds your code.** Controllers, models, providers, and middleware live here. Laravel 11 slimmed it down by removing rarely-touched files.
2. **`bootstrap/app.php` is the new configuration hub.** Routing, middleware, and exceptions are configured here — not in separate kernel files.
3. **`config/` files are published on demand.** Laravel 11 ships fewer config files and falls back to framework defaults for missing ones.
4. **`database/` includes the default SQLite file.** Laravel 11+ uses SQLite by default, requiring zero database server setup.
5. **`public/` is the document root.** Only `index.php` and compiled assets belong here. Never expose the project root.
6. **`resources/` holds uncompiled assets.** Blade views, CSS, JS, and (in Laravel 11+) translation files.
7. **`storage/` and `bootstrap/cache/` must be writable.** These hold logs, sessions, compiled views, and optimization caches.
8. **`artisan` is your CLI entrypoint.** Use it for scaffolding, migrations, optimization, and running the development server.
9. **`vite.config.js` manages frontend assets.** Vite provides fast HMR in development and optimized builds in production.
10. **`vendor/` is never committed.** Run `composer install --no-dev --optimize-autoloader` in production.
