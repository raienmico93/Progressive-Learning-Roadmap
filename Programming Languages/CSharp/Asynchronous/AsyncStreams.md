# C# Asynchronous Streams — Comprehensive Programming Cheat Sheet

---

## Topic Overview

### Definitions

**Core Definition**
An asynchronous stream is a **sequence of data that is produced and consumed asynchronously**, element by element, without blocking the calling thread and without materializing the entire sequence in memory. It is the asynchronous counterpart of `IEnumerable<T>`, represented by the `IAsyncEnumerable<T>` interface and consumed with the `await foreach` statement. Asynchronous streams were introduced in **C# 8.0** and **.NET Core 3.0** to solve a fundamental limitation: before them, an asynchronous method could return only a single value (via `Task<T>`), or it had to buffer an entire collection before returning it (via `Task<List<T>>` or `Task<IEnumerable<T>>`).

**Technical Definition**
An asynchronous stream is a type that implements `IAsyncEnumerable<T>`. The interface exposes a single method, `GetAsyncEnumerator(CancellationToken)`, which returns an `IAsyncEnumerator<T>`. The enumerator exposes a `Current` property of type `T` and a `MoveNextAsync()` method that returns `ValueTask<bool>`. The enumerator also implements `IAsyncDisposable`, so it can be disposed asynchronously via `await using`. The C# compiler provides **async iterator methods**—methods marked `async` that return `IAsyncEnumerable<T>` or `IAsyncEnumerator<T>` and use both `await` expressions and `yield return` statements—which generate state machines implementing these interfaces automatically. The `await foreach` statement consumes an asynchronous stream by lowering to repeated `await MoveNextAsync()` calls and an `await DisposeAsync()` call. The `[EnumeratorCancellation]` attribute marks a `CancellationToken` parameter so that the compiler wires the token supplied via `WithCancellation` on the consumer side into the iterator's cancellation token, combining both via `CancellationTokenSource.CreateLinkedTokenSource`.

**Beginner-Friendly Explanation**
An asynchronous stream is a **pipe of data that delivers items one at a time, asynchronously**. Imagine drinking from a water fountain: you get a sip, swallow it, then get the next sip when you are ready. You do not have to wait for the entire reservoir to be bottled before you start drinking. Before asynchronous streams, if you wanted to process a million database rows asynchronously, you had two bad options: wait for all one million rows to load into memory first (`Task<List<T>>`), or write complex manual async enumeration code. Asynchronous streams fix this: you write a method that `yield return`s each row after an `await` (e.g., `await reader.ReadAsync()`), and the caller consumes it with `await foreach`. Each element is produced only when the consumer is ready for it, memory usage stays flat (one element at a time), and the thread is never blocked while waiting for I/O.

---

### Key Characteristics

- **Element-by-element streaming** — Items are produced and consumed one at a time, not buffered as a whole collection.
- **Asynchronous production and consumption** — Both the producer (`MoveNextAsync`) and the consumer (`await foreach`) can perform asynchronous work without blocking threads.
- **`IAsyncEnumerable<T>` is the contract** — Any type implementing this interface is an asynchronous stream.
- **Compiler-generated async iterators** — Methods using `async` + `yield return` are rewritten into state machines implementing `IAsyncEnumerable<T>` and `IAsyncEnumerator<T>`.
- **Cancellation is first-class** — A `CancellationToken` flows from the consumer into the iterator via the `[EnumeratorCancellation]` attribute.
- **`await using` for disposal** — Enumerators are disposed asynchronously (`IAsyncDisposable`).
- **`ConfigureAwait(false)` support** — Async streams support context capture control on the consumer side.
- **Flat memory profile** — Memory usage is proportional to the element size, not the collection size, making it suitable for unbounded or very large sequences.

---

### Prerequisites

- Solid understanding of **`async` and `await`** and the Task-based Asynchronous Pattern (TAP).
- Familiarity with **`IEnumerable<T>`** and synchronous iterators (`yield return`).
- Knowledge of **`CancellationToken`** and cooperative cancellation.
- Awareness of **`IAsyncDisposable`** and `await using`.
- Basic understanding of **state machines** generated by the compiler (helpful but not required).

---

### Related Programming Areas

- **Async/await** — Asynchronous streams are built on top of the async state-machine infrastructure.
- **Task-based Asynchronous Pattern (TAP)** — `IAsyncEnumerable<T>` is the streaming counterpart of `Task<T>`.
- **LINQ** — Many LINQ operators have async counterparts in `System.Linq.Async` (e.g., `WhereAwait`, `SelectAwait`).
- **Channels** — `System.Threading.Channels` provides bounded and unbounded async producer/consumer queues that integrate with `IAsyncEnumerable<T>`.
- **I/O programming** — Database readers, network streams, and file readers are natural sources of async streams.

## 1. Asynchronous Streams (Overarching Concept)

### Definitions

**Core Definition**
An asynchronous stream is an asynchronous sequence of values that can be enumerated element by element, where obtaining each element may involve an asynchronous operation.

**Technical Definition**
Async streams are asynchronous variants of enumerables, where getting the next element may involve an asynchronous operation. They are types that implement `IAsyncEnumerable<T>`. The feature consists of the `IAsyncEnumerable<T>` and `IAsyncEnumerator<T>` interfaces, the `await foreach` statement for consumption, and async iterator methods (`async` + `yield return`) for production. Async streams solve the limitation of `Task<T>` (single value) and `Task<List<T>>` (entire collection buffered before processing) by allowing elements to be delivered as they become available.

**Beginner-Friendly Explanation**
An asynchronous stream is a **lazy, non-blocking sequence**. You request an item, the producer asynchronously prepares it, and you receive it when it is ready—without blocking your thread and without waiting for the rest of the sequence.

---

### Purposes

- To process **large or unbounded sequences** without loading everything into memory.
- To consume data **as it arrives** (streaming from a database, network, or file).
- To keep the **UI thread responsive** while iterating over asynchronously produced data.
- To enable **backpressure-friendly** consumption (the consumer pulls elements at its own pace).
- To provide a **natural programming model** for asynchronous data sources, replacing complex manual async enumeration patterns.

---

### Syntax Rules and Structure

```
// Producer: async iterator method
async IAsyncEnumerable<T> ProduceAsync()
{
    while (condition)
    {
        T item = await GetNextAsync();
        yield return item;
    }
}

// Consumer: await foreach
await foreach (T item in ProduceAsync())
{
    // process item
}
```

**Component breakdown**

- `async` — Marks the method as asynchronous and enables `yield return`.
- `IAsyncEnumerable<T>` — The return type of an async iterator.
- `await` — Suspends the iterator until the next element is ready.
- `yield return` — Produces an element to the consumer.
- `await foreach` — Consumes the stream asynchronously.

#### Syntax Rules

- An async iterator must be marked `async` and return `IAsyncEnumerable<T>` or `IAsyncEnumerator<T>`.
- It must contain at least one `yield return` (and optionally `yield break`).
- `yield return` cannot appear in a `try` block with a `catch` clause; it cannot appear in a `finally` block.
- `await foreach` can only be used on types that implement `IAsyncEnumerable<T>` (or have a compatible `GetAsyncEnumerator` method).

#### Constraints and Limitations

- Asynchronous streams are **single-use**; each enumeration calls `GetAsyncEnumerator` afresh, but the underlying source may not be re-enumerable.
- `yield return` cannot be used in a `try` with `catch`; use `await using` for async disposal instead.
- Async streams do not support `ConfigureAwait` on the producer side directly; use `.ConfigureAwait(false)` on the consumer side.

---

### Annotated Code Examples and Expected Outputs

#### Example 1: Producing and Consuming an Async Stream

```csharp
using System;
using System.Collections.Generic;
using System.Threading.Tasks;

class Program
{
    static async IAsyncEnumerable<int> GenerateNumbersAsync(int count, int delayMs)
    {
        for (int i = 0; i < count; i++)
        {
            await Task.Delay(delayMs);   // simulate async work
            yield return i;
        }
    }

    static async Task Main()
    {
        await foreach (int number in GenerateNumbersAsync(5, 1000))
        {
            Console.WriteLine($"Received: {number}");
        }
    }
}
```

**Expected Output**
```
Received: 0
(1 second pause)
Received: 1
(1 second pause)
Received: 2
(1 second pause)
Received: 3
(1 second pause)
Received: 4
```

**Why this output occurs**
Each iteration awaits `Task.Delay`, produces an element with `yield return`, and the consumer receives it before the next delay begins. The thread is not blocked during the delay.

---

#### Example 2: Filtering an Async Stream with `await foreach`

```csharp
using System;
using System.Collections.Generic;
using System.Threading.Tasks;

class Program
{
    static async IAsyncEnumerable<int> GetResultsAsync()
    {
        for (int i = 0; i < 10; i++)
        {
            await Task.Delay(50);
            yield return i;
        }
    }

    static async Task Main()
    {
        await foreach (var result in GetResultsAsync())
        {
            if (result > 5)
                yield return result;   // ERROR: cannot use yield in await foreach
        }
    }
}
```

**Note:** You cannot use `yield return` directly inside an `await foreach` in a method that is not itself an async iterator. To filter an async stream, wrap it in another async iterator:

```csharp
static async IAsyncEnumerable<int> FilterAsync(IAsyncEnumerable<int> source)
{
    await foreach (var item in source)
    {
        if (item > 5)
            yield return item;
    }
}
```

**Expected Output**
```
(no output shown; the second example demonstrates the correct pattern)
```

**Why this pattern is needed**
`yield return` requires the enclosing method to be an async iterator returning `IAsyncEnumerable<T>`. Filtering must be done by composing async iterators, not by mixing `yield` into a consuming `await foreach`.

- **Log tailing** — Streaming new lines from a log file as they are appended.
- **WebSocket frames** — Processing frames as they arrive from a socket.
- **Paged API consumption** — Fetching pages of results asynchronously and yielding each item.

## 2. `IAsyncEnumerable<T>`

### Definitions

**Core Definition**
`IAsyncEnumerable<T>` is the interface representing an asynchronous sequence of `T` values, exposing a method to obtain an asynchronous enumerator.

**Technical Definition**
`System.Collections.Generic.IAsyncEnumerable<out T>` declares a single method: `IAsyncEnumerator<T> GetAsyncEnumerator(CancellationToken cancellationToken = default)`. The `out` modifier makes the type covariant in `T`. The returned `IAsyncEnumerator<T>` exposes a `Current` property of type `T`, a `MoveNextAsync()` method returning `ValueTask<bool>`, and implements `IAsyncDisposable` for asynchronous cleanup. This interface is the asynchronous counterpart of `IEnumerable<T>` and is the foundation of async streams.

**Beginner-Friendly Explanation**
`IAsyncEnumerable<T>` is the **contract for an asynchronous sequence**. Anything implementing it can be iterated with `await foreach`.

---

### Purposes

- To provide a **standard contract** for asynchronous sequences.
- To enable `await foreach` over asynchronous data sources.
- To support **cancellation** via the `CancellationToken` parameter.
- To enable **covariance** (`out T`) so that `IAsyncEnumerable<Derived>` can be used as `IAsyncEnumerable<Base>`.
- To serve as the return type for async iterator methods.

---

### Syntax Rules and Structure

```csharp
public interface IAsyncEnumerable<out T>
{
    IAsyncEnumerator<T> GetAsyncEnumerator(CancellationToken cancellationToken = default);
}

public interface IAsyncEnumerator<out T> : IAsyncDisposable
{
    T Current { get; }
    ValueTask<bool> MoveNextAsync();
}
```

**Component breakdown**

- `GetAsyncEnumerator` — Returns the enumerator; accepts an optional `CancellationToken`.
- `MoveNextAsync` — Advances to the next element asynchronously; returns `ValueTask<bool>`.
- `Current` — The current element.
- `IAsyncDisposable` — Provides `DisposeAsync()` for asynchronous cleanup.

#### Syntax Rules

- `IAsyncEnumerable<T>` is covariant (`out T`).
- `MoveNextAsync` returns `ValueTask<bool>` (not `Task<bool>`) to avoid unnecessary allocations.
- The enumerator must be disposed asynchronously with `await using` or `await foreach`'s implicit disposal.

#### Constraints and Limitations

- The enumerator is **single-use**; it cannot be reset.
- The underlying source may not be re-enumerable; each call to `GetAsyncEnumerator` may start a new iteration or may not be supported.
- `Current` is undefined before the first successful `MoveNextAsync` and after it returns `false`.

---

### Annotated Code Examples and Expected Outputs

#### Example: Implementing `IAsyncEnumerable<T>` Manually

```csharp
using System;
using System.Collections.Generic;
using System.Threading;
using System.Threading.Tasks;

public class AsyncRange : IAsyncEnumerable<int>
{
    private readonly int _count;
    public AsyncRange(int count) => _count = count;

    public async IAsyncEnumerator<int> GetAsyncEnumerator(
        CancellationToken cancellationToken = default)
    {
        for (int i = 0; i < _count; i++)
        {
            await Task.Delay(100, cancellationToken);
            yield return i;
        }
    }
}

class Program
{
    static async Task Main()
    {
        var range = new AsyncRange(3);
        await foreach (var n in range)
            Console.WriteLine(n);
    }
}
```

**Expected Output**
```
0
1
2
```

**Why this output occurs**
`AsyncRange` implements `IAsyncEnumerable<int>` by providing an async iterator (`GetAsyncEnumerator`) that yields elements with a delay. The consumer iterates with `await foreach`.

---

- **Custom data sources** — Wrapping a database reader, message queue, or socket as `IAsyncEnumerable<T>`.
- **LINQ async operators** — `System.Linq.Async` extends `IAsyncEnumerable<T>` with async query operators.
- **gRPC streaming** — Server-streaming calls expose `IAsyncEnumerable<T>`.

## 3. `await foreach`

### Definitions

**Core Definition**
`await foreach` is a C# statement that **asynchronously iterates over an `IAsyncEnumerable<T>`**, awaiting each element as it becomes available.

**Technical Definition**
The `await foreach` statement is just like a `foreach` statement, but it uses `IAsyncEnumerable` instead of `IEnumerable`; each iteration evaluates an `await MoveNextAsync()`, and the enumerator is disposed asynchronously via `await DisposeAsync()`. The compiler lowers `await foreach` into a `while` loop that repeatedly calls `await MoveNextAsync()` and accesses `Current`, with an `await using` for the enumerator. The consumer can optionally call `.ConfigureAwait(false)` or `.WithCancellation(token)` on the async stream to control context capture and cancellation.

**Beginner-Friendly Explanation**
`await foreach` is **`foreach` for async streams**. It pauses the loop without blocking the thread, waiting for each element to arrive.

---

### Purposes

- To consume asynchronous streams elegantly and safely.
- To avoid manual `MoveNextAsync` loops and disposal handling.
- To propagate cancellation from the consumer to the producer.
- To control synchronization-context capture with `ConfigureAwait(false)`.

---

### Syntax Rules and Structure

```csharp
await foreach (T item in asyncStream)
{
    // process item
}
```

**Component breakdown**

- `await` — Indicates asynchronous iteration.
- `foreach` — The iteration keyword.
- `T item` — The iteration variable.
- `asyncStream` — An `IAsyncEnumerable<T>` (or compatible).

#### Syntax Rules

- `await foreach` can only be used in an `async` method.
- The stream must implement `IAsyncEnumerable<T>` or have a compatible `GetAsyncEnumerator` pattern.
- The enumerator is disposed asynchronously after the loop (including on `break` or exception).
- `.ConfigureAwait(false)` and `.WithCancellation(token)` can be chained on the stream expression.

#### Constraints and Limitations

- Cannot be used in a non-async method.
- Cannot be used on `IEnumerable<T>` (use regular `foreach`).
- The iteration variable is read-only.

---

### Annotated Code Examples and Expected Outputs

#### Example 1: Basic `await foreach`

```csharp
using System;
using System.Collections.Generic;
using System.Threading.Tasks;

class Program
{
    static async IAsyncEnumerable<string> GetMessagesAsync()
    {
        yield return "Hello";
        await Task.Delay(100);
        yield return "World";
    }

    static async Task Main()
    {
        await foreach (var message in GetMessagesAsync())
            Console.WriteLine(message);
    }
}
```

**Expected Output**
```
Hello
World
```

**Why this output occurs**
`await foreach` pulls each element asynchronously; the delay between elements does not block the thread.

---

#### Example 2: `ConfigureAwait(false)` and `WithCancellation`

```csharp
using System;
using System.Collections.Generic;
using System.Threading;
using System.Threading.Tasks;

class Program
{
    static async IAsyncEnumerable<int> GetDataAsync(
        [System.Runtime.CompilerServices.EnumeratorCancellation] CancellationToken ct = default)
    {
        for (int i = 0; i < 10; i++)
        {
            ct.ThrowIfCancellationRequested();
            await Task.Delay(100, ct);
            yield return i;
        }
    }

    static async Task Main()
    {
        using var cts = new CancellationTokenSource(500);
        try
        {
            await foreach (var item in GetDataAsync().WithCancellation(cts.Token).ConfigureAwait(false))
                Console.WriteLine(item);
        }
        catch (OperationCanceledException)
        {
            Console.WriteLine("Cancelled");
        }
    }
}
```

**Expected Output (approximate)**
```
0
1
2
3
4
Cancelled
```

**Why this output occurs**
`.WithCancellation` propagates the token to the iterator (thanks to `[EnumeratorCancellation]`), and `.ConfigureAwait(false)` avoids capturing the synchronization context. The loop cancels when the token fires.

---

### Real-World Cases

- **API controllers** — `await foreach` over streaming responses.
- **UI applications** — Consuming async streams without freezing the UI.
- **Data pipelines** — Processing database rows or log lines as they arrive.

## 4. `yield return` in Async Iterators

### Definitions

**Core Definition**
`yield return` inside an `async` method returning `IAsyncEnumerable<T>` produces an element of the asynchronous stream and suspends the iterator until the consumer requests the next element.

**Technical Definition**
An async iterator method is a method that (1) is declared `async`, (2) returns `IAsyncEnumerable<T>` or `IAsyncEnumerator<T>`, and (3) uses both `await` expressions and `yield` statements. The compiler generates a state machine that implements `IAsyncEnumerator<T>` directly, with `MoveNextAsync` returning `ValueTask<bool>`. The state machine is conceptually the union of the async state machine and the synchronous yield-based enumerator. `yield return` produces one element; `yield break` terminates the stream. `yield return` cannot appear in a `try` block that has `catch` clauses, and neither form can appear in a `finally` block.

**Beginner-Friendly Explanation**
`yield return` is the **"produce one item and pause"** instruction. The method resumes when the consumer asks for the next item.

---

### Purposes

- To produce asynchronous streams element by element.
- To combine `await` (for asynchronous work) with `yield` (for element production).
- To write streaming producers that are lazy and memory-efficient.
- To enable composition of async iterators (e.g., filtering, transformation).

---

### Syntax Rules and Structure

```csharp
async IAsyncEnumerable<T> ProduceAsync()
{
    // async work
    await SomethingAsync();
    yield return item;

    // more async work
    await SomethingElseAsync();
    yield return item2;
}
```

**Component breakdown**

- `async` — Required modifier.
- `IAsyncEnumerable<T>` — Required return type.
- `await` — Asynchronous suspension.
- `yield return` — Produces an element.
- `yield break` — Ends the stream early.

#### Syntax Rules

- The method must be `async` and return `IAsyncEnumerable<T>` or `IAsyncEnumerator<T>`.
- `yield return` and `yield break` are allowed, but `yield return` cannot be in a `try` with `catch`, and neither can be in a `finally`.
- The method cannot have `ref` or `out` parameters.
- `yield return` cannot be used in a method that returns `Task` or `Task<T>`; only `IAsyncEnumerable<T>`/`IAsyncEnumerator<T>`.

#### Constraints and Limitations

- `yield return` in an async iterator cannot be used in a `try` with `catch`; use `await using` for cleanup instead.
- The state machine generated by the compiler handles both `await` and `yield`; the combination has some restrictions on control flow.

---

### Annotated Code Examples and Expected Outputs

#### Example: Async Iterator with `await` and `yield return`

```csharp
using System;
using System.Collections.Generic;
using System.Threading.Tasks;

class Program
{
    static async IAsyncEnumerable<int> GetValuesAsync()
    {
        for (int i = 0; i < 5; i++)
        {
            await Task.Delay(100);
            yield return i * 10;
        }
    }

    static async Task Main()
    {
        await foreach (var value in GetValuesAsync())
            Console.WriteLine(value);
    }
}
```

**Expected Output**
```
0
10
20
30
40
```

**Why this output occurs**
Each iteration awaits a delay and then yields a value; the consumer receives each value asynchronously.

---

- **Database readers** — `await reader.ReadAsync()` → `yield return reader.CurrentRow`.
- **Paged APIs** — Fetch pages asynchronously and `yield return` each item.
- **Log tailing** — Read new lines asynchronously and yield them.

## 5. `[EnumeratorCancellation]`

### Definitions

**Core Definition**
`[EnumeratorCancellation]` is an attribute that marks a `CancellationToken` parameter of an async iterator method, instructing the compiler to wire the token supplied by the consumer (via `WithCancellation`) into the iterator's cancellation token.

**Technical Definition**
`System.Runtime.CompilerServices.EnumeratorCancellationAttribute` allows users of async-enumerable methods to mark the parameter that should receive the cancellation token value from `GetAsyncEnumerator(CancellationToken)`. The attribute **does not** affect the generated state machine's body; instead, it marks the parameter so that the C#-emitted `GetAsyncEnumerator(CancellationToken)` overload combines the parameter's value with the value passed to `WithCancellation(...)` using `CancellationTokenSource.CreateLinkedTokenSource`. The combined token replaces the parameter inside the iterator at the point of enumeration. Without the attribute, the token passed to `WithCancellation` never reaches the iterator's cancellation token local—a silent bug.

**Beginner-Friendly Explanation**
`[EnumeratorCancellation]` is the **"connect the cancellation token"** attribute. It ensures that when the consumer cancels, the producer's `CancellationToken` is actually cancelled.

---

### Purposes

- To propagate cancellation from the consumer (`await foreach … WithCancellation(token)`) to the producer's `CancellationToken`.
- To combine multiple cancellation sources (the token passed at method invocation and the token passed at enumeration).
- To prevent a common bug where cancellation is silently ignored by the iterator.

---

### Syntax Rules and Structure

```csharp
async IAsyncEnumerable<T> GetDataAsync(
    [EnumeratorCancellation] CancellationToken cancellationToken = default)
{
    // use cancellationToken inside
}
```

**Component breakdown**

- `[EnumeratorCancellation]` — Attribute on the `CancellationToken` parameter.
- `CancellationToken cancellationToken` — The parameter that receives the combined token.

#### Syntax Rules

- The parameter must be of type `CancellationToken`.
- The attribute can be applied to only one parameter per async iterator method.
- The parameter typically has a default value (`= default`).
- The attribute is in the `System.Runtime.CompilerServices` namespace.

#### Constraints and Limitations

- Without the attribute, `WithCancellation` does not affect the iterator's token; only the `await` around `MoveNextAsync` is cancelled.
- The combined token is created via `CreateLinkedTokenSource`; the original tokens are not replaced, and `OperationCanceledException.CancellationToken` reflects the linked token, not the original.

---

### Annotated Code Examples and Expected Outputs

#### Example: Cancellation Propagation with `[EnumeratorCancellation]`

```csharp
using System;
using System.Collections.Generic;
using System.Runtime.CompilerServices;
using System.Threading;
using System.Threading.Tasks;

class Program
{
    static async IAsyncEnumerable<int> CountAsync(
        [EnumeratorCancellation] CancellationToken ct = default)
    {
        for (int i = 0; ; i++)
        {
            ct.ThrowIfCancellationRequested();
            await Task.Delay(100, ct);
            yield return i;
        }
    }

    static async Task Main()
    {
        using var cts = new CancellationTokenSource(500);
        try
        {
            await foreach (var n in CountAsync().WithCancellation(cts.Token))
                Console.WriteLine(n);
        }
        catch (OperationCanceledException)
        {
            Console.WriteLine("Cancelled");
        }
    }
}
```

**Expected Output**
```
0
1
2
3
4
Cancelled
```

**Why this output occurs**
The `[EnumeratorCancellation]` attribute ensures that the token passed to `WithCancellation` is combined with the iterator's `ct` parameter. When the `CancellationTokenSource` fires after 500ms, `ct.ThrowIfCancellationRequested()` throws, and the loop terminates with `OperationCanceledException`.

---

### Real-World Cases

- **Database streaming** — Cancelling a long-running query when the client disconnects.
- **Web API streaming** — Propagating `HttpContext.RequestAborted` into async iterators.
- **UI streaming** — Cancelling background data streams when the user navigates away.

## 6. Asynchronous Streams Best Practices

### Definitions

**Core Definition**
Asynchronous streams best practices are the guidelines that ensure async streams are **correct, efficient, cancellable, and memory-safe**, avoiding common pitfalls such as missing cancellation propagation and improper disposal.

**Technical Definition**
Best practices for async streams derive from the C# and .NET documentation. Key recommendations include: **always use `[EnumeratorCancellation]`** on the `CancellationToken` parameter of async iterators; **use `await foreach` instead of manual `MoveNextAsync` loops**; **dispose enumerators asynchronously** (`await using`); **prefer `IAsyncEnumerable<T>` over `Task<List<T>>` for large or unbounded sequences**; **use `ConfigureAwait(false)` in library code**; **avoid `yield return` in `try` with `catch`**; **stream, don't buffer**; and **propagate cancellation throughout the pipeline**.

**Beginner-Friendly Explanation**
The best practices are: **connect cancellation**, **use `await foreach`**, **dispose properly**, and **stream instead of buffering**.

---

### Guidelines and Structure

#### General Guidelines

```csharp
// 1. Always use [EnumeratorCancellation] on the token parameter
async IAsyncEnumerable<Row> ReadAsync(
    [EnumeratorCancellation] CancellationToken ct = default) { ... }

// 2. Use await foreach instead of manual MoveNextAsync
await foreach (var item in stream.WithCancellation(ct).ConfigureAwait(false))
    Process(item);

// 3. Dispose enumerators asynchronously
await using var enumerator = stream.GetAsyncEnumerator();
while (await enumerator.MoveNextAsync())
    Process(enumerator.Current);

// 4. Prefer IAsyncEnumerable<T> over Task<List<T>> for streaming
// Bad: Task<List<Row>> GetRowsAsync()
// Good: IAsyncEnumerable<Row> GetRowsAsync()

// 5. Avoid yield return inside try-with-catch
// Use await using for async cleanup instead.
```

**Component breakdown**

- **`[EnumeratorCancellation]`** — Required for cancellation propagation.
- **`await foreach`** — Preferred consumption pattern.
- **`await using`** — Proper asynchronous disposal.
- **`IAsyncEnumerable<T>`** — Streaming shape for large/unbounded sequences.
- **No `yield` in `try`/`catch`** — Language restriction.

#### Rules and Constraints

- **Do** use `[EnumeratorCancellation]` on the token parameter.
- **Do** use `await foreach` with `.WithCancellation` and `.ConfigureAwait(false)`.
- **Do** prefer `IAsyncEnumerable<T>` for streaming scenarios.
- **Do** dispose async enumerators with `await using`.
- **Do not** buffer entire sequences with `Task<List<T>>` when streaming is possible.
- **Do not** omit cancellation propagation; it silently breaks cancellation.
- **Do not** use `yield return` inside `try` blocks with `catch` clauses.

### Annotated Code Examples and Expected Outputs

#### Example: Well-Designed Async Stream

```csharp
using System;
using System.Collections.Generic;
using System.Runtime.CompilerServices;
using System.Threading;
using System.Threading.Tasks;

public class Row { public int Id { get; set; } }

public class Repository
{
    public async IAsyncEnumerable<Row> StreamRowsAsync(
        [EnumeratorCancellation] CancellationToken ct = default)
    {
        for (int i = 0; i < 10; i++)
        {
            ct.ThrowIfCancellationRequested();
            await Task.Delay(50, ct).ConfigureAwait(false);
            yield return new Row { Id = i };
        }
    }
}

class Program
{
    static async Task Main()
    {
        var repo = new Repository();
        using var cts = new CancellationTokenSource(200);

        await foreach (var row in repo.StreamRowsAsync().WithCancellation(cts.Token).ConfigureAwait(false))
            Console.WriteLine(row.Id);
    }
}
```

**Expected Output (approximate)**
```
0
1
2
3
Cancelled (via OperationCanceledException, not shown in snippet)
```

**Why this output occurs**
The repository method follows best practices: it uses `[EnumeratorCancellation]`, checks cancellation, uses `ConfigureAwait(false)`, and the consumer uses `await foreach` with `WithCancellation` and `ConfigureAwait(false)`.

| Feature | Status / Note |
|---|---|
| Asynchronous streams | Introduced in **C# 8.0 / .NET Core 3.0**; stable. |

| `await foreach` | Core language feature; stable. |

| `[EnumeratorCancellation]` | Introduced with async streams; stable. |
| `IAsyncDisposable` / `await using` | Introduced with async streams; stable. |
| `WithCancellation` | Extension method on `IAsyncEnumerable<T>`; stable. |
