# Template Fundamentals — Comprehensive Programming Cheat Sheet

---

## Topic Overview

### Definitions

**Core Definition**
A template is a C++ construct that defines a **family of classes, functions, or variables** parameterized by one or more types or values, allowing the same code to work with many different types without duplication.

**Technical Definition**
A template is a C++ entity that defines a family of classes (class template), a family of functions (function template), an alias to a family of types (alias template, C++11), or a family of variables (variable template, C++14) . Templates are parameterized by one or more template parameters of three kinds: **type template parameters**, **non-type template parameters**, and **template template parameters** . When template arguments are provided or deduced, they are substituted for the template parameters to obtain a **specialization** of the template—a specific type or function. Specializations may be provided explicitly: **full specializations** are allowed for class, variable, and function templates; **partial specializations** are only allowed for class templates and variable templates . When a specialization is referenced in a context requiring a complete type or function definition, the template is **instantiated** (the code is compiled), unless already specialized or explicitly instantiated . Instantiation of a class template does not instantiate its member functions unless they are used. At link time, identical instantiations from different translation units are merged .

**Beginner-Friendly Explanation**
A template is a **blueprint for a blueprint**. Instead of writing a function that swaps two `int`s, another that swaps two `double`s, and another that swaps two `std::string`s, you write **one template** that says “swap two things of some type `T`.” When you use it with `int`, the compiler generates an `int` version; when you use it with `double`, it generates a `double` version. Templates are how C++ does **generic programming**: writing code that works with any type that supports the required operations. They power the entire standard library—`std::vector<T>`, `std::sort`, `std::map`—and are the foundation of modern C++ abstraction. The trade-off is complexity: templates can produce long error messages, increase compile times, and require careful design.

### Key Characteristics

- **Generic programming**: Write once, work with many types.
- **Compile-time instantiation**: The compiler generates concrete code for each type combination.
- **Three parameter kinds**: Type, non-type (values), and template template parameters.
- **Specialization**: Customize behavior for specific types (full or partial).
- **Header-only libraries**: Template definitions must be visible at instantiation, so they typically live in headers .
- **Zero-overhead abstraction**: Templates incur no runtime cost compared to hand-written code.
- **Code bloat risk**: Each instantiation generates separate code.

### Prerequisites

- Understanding of functions, classes, and data types.
- Familiarity with overloading and type deduction.
- Knowledge of headers and compilation model.
- Basic awareness of the standard library containers and algorithms.

### Related Programming Areas

- **Generic programming** – the paradigm templates enable.
- **Standard Template Library (STL)** – containers, iterators, algorithms.
- **Template metaprogramming** – compile-time computation.
- **Concepts (C++20)** – constrained templates.
- **Variadic templates (C++11)** – parameter packs.
- **Perfect forwarding** – forwarding references in templates.

## 1. Templates

### Definitions

**Core Definition**
A template is a parameterized C++ entity from which specific types or functions are generated by substituting template arguments.

**Technical Definition**
A template defines a family of classes, functions, aliases, or variables, parameterized by template parameters . The `template` keyword introduces a template parameter list, followed by a declaration. Templates are not compiled into code themselves; they are patterns from which the compiler generates **specializations** when arguments are provided or deduced.

**Beginner-Friendly Explanation**
A template is a **reusable pattern** that the compiler turns into real code when you give it the missing type information.

### Purposes

- To write generic code that works with many types.
- To eliminate duplication across type-specific implementations.
- To enable zero-overhead abstractions.
- To power the standard library.

### Syntax Rules and Structure

**General Syntax**
```cpp
template < parameter-list >
declaration
```

**Component Breakdown**

| Component | Description |
|-----------|-------------|
| `template` | Keyword introducing the template. |
| `< parameter-list >` | Comma-separated template parameters. |
| `declaration` | The class, function, alias, or variable definition. |

**Syntax Rules**
- The parameter list is non-empty and comma-separated .
- Parameters may be types, non-types, template templates, or packs.
- Templates can be declared at namespace or class scope.

**Constraints and Limitations**
- Template definitions must typically be in headers (visible at instantiation) .
- Templates cannot be compiled separately in the traditional sense.

### Annotated Code Examples

**Example 1: Basic function template**

```cpp
#include <iostream>

template <typename T>
T max(T a, T b) {
    return a > b ? a : b;
}

int main() {
    std::cout << max(3, 7) << '\n';       // T = int
    std::cout << max(2.5, 1.5) << '\n';   // T = double
}
```

**Expected Output**
```
7
2.5
```

**Why this output?**  
The compiler deduces `T = int` for the first call and `T = double` for the second, generating two specializations.

### Real-World Cases

- **`std::vector<T>`** – dynamic array for any type.
- **`std::sort`** – sorting algorithm for any random-access range.
- **`std::make_unique<T>`** – factory for any type.

## 2. Function Templates

### Definitions

**Core Definition**
A function template defines a family of functions parameterized by template parameters, from which the compiler generates concrete functions based on argument types.

**Technical Definition**
A function template is a template that defines a family of functions . When called, template arguments are deduced from the function arguments (or explicitly provided), and the compiler instantiates the corresponding function specialization. Function templates can be overloaded with other function templates and with non-template functions .

**Beginner-Friendly Explanation**
A function template is a **generic function** that adapts to the types you pass. `template <typename T> T max(T a, T b)` becomes `max<int>` or `max<double>` automatically.

### Purposes

- To write type-generic functions.
- To avoid duplicating logic for each type.
- To support generic algorithms and utilities.

### Syntax Rules and Structure

**General Syntax**
```cpp
template <typename T>
T function_name(T param1, T param2) {
    // ...
}
```

**Component Breakdown**

| Component | Description |
|-----------|-------------|
| `template <typename T>` | Template parameter list. |
| `T function_name(...)` | Function using `T`. |

**Syntax Rules**
- `typename` and `class` are interchangeable for type parameters .
- Template arguments can be deduced from function arguments.
- Explicit arguments can be provided: `max<int>(a, b)`.

**Constraints and Limitations**
- All template parameters must normally appear in the function parameter list (unless deduced elsewhere) .
- The type must support the operations used in the function body.

### Annotated Code Examples

**Example 1: Function template with deduction**

```cpp
#include <iostream>

template <typename T>
void swap_values(T& a, T& b) {
    T temp = a;
    a = b;
    b = temp;
}

int main() {
    int x = 1, y = 2;
    swap_values(x, y);
    std::cout << x << ' ' << y << '\n';
}
```

**Expected Output**
```
2 1
```

**Why this output?**  
`T` is deduced as `int`; the template swaps the two integers.

### Real-World Cases

- **`std::swap`** – swaps any two objects.
- **`std::min` / `std::max`** – generic comparisons.
- **`std::find`** – searches any container.

## 3. Class Templates

### Definitions

**Core Definition**
A class template defines a family of classes parameterized by template parameters, from which the compiler generates concrete classes when arguments are provided.

**Technical Definition**
A class template is a template that defines a family of classes . To use it, you provide template arguments (or, since C++17, they may be deduced for class templates in some contexts). Each combination of arguments produces a distinct class specialization. Member functions are instantiated only when used . The template definition must be visible at the point of instantiation.

**Beginner-Friendly Explanation**
A class template is a **generic class**. `std::vector<int>` and `std::vector<std::string>` are two different classes generated from the same `vector<T>` template.

### Purposes

- To create type-safe containers.
- To implement generic data structures.
- To support policy-based design.

### Syntax Rules and Structure

**General Syntax**
```cpp
template <typename T>
class ClassName {
    T member_;
public:
    ClassName(T value) : member_(value) {}
    T get() const { return member_; }
};
```

**Component Breakdown**

| Component | Description |
|-----------|-------------|
| `template <typename T>` | Template parameter list. |
| `class ClassName { ... }` | Class definition using `T`. |

**Syntax Rules**
- Template arguments must be provided (or deduced since C++17) when creating objects: `ClassName<int> obj;`.
- Member functions defined outside the class need the template header and qualification.
- Each instantiation is a distinct type.

**Constraints and Limitations**
- Member functions are instantiated only when used .
- Different instantiations are unrelated types (no implicit conversion between `ClassName<int>` and `ClassName<double>`).

### Annotated Code Examples

**Example 1: Class template**

```cpp
#include <iostream>

template <typename T>
class Box {
    T value_;
public:
    explicit Box(T value) : value_(value) {}
    T get() const { return value_; }
};

int main() {
    Box<int> b1(42);
    Box<std::string> b2("hello");
    std::cout << b1.get() << ' ' << b2.get() << '\n';
}
```

**Expected Output**
```
42 hello
```

**Why this output?**  
`Box<int>` and `Box<std::string>` are distinct specializations; each stores and returns its respective type.

### Real-World Cases

- **`std::vector<T>`** – dynamic array.
- **`std::map<K, V>`** – associative container.
- **`std::unique_ptr<T>`** – smart pointer.

## 4. Template Parameters

### Definitions

**Core Definition**
Template parameters are the placeholders (types, values, or templates) that a template is parameterized by.

**Technical Definition**
There are three kinds of template parameters :
- **Type template parameters**: introduced by `typename` or `class`.
- **Non-type template parameters**: constants of integral, enumeration, pointer, or reference type (and more in C++20).
- **Template template parameters**: parameters that are themselves templates.

Parameter packs (C++11) represent zero or more parameters .

**Beginner-Friendly Explanation**
Template parameters are the **blanks to fill in**. `template <typename T>` declares `T` as a type parameter; `template <int N>` declares `N` as a value parameter.

### Purposes

- To parameterize templates by type, value, or template.
- To support generic and policy-based design.
- To enable compile-time configuration.

### Syntax Rules and Structure

**Type Parameter**
```cpp
template <typename T>
```

**Non-Type Parameter**
```cpp
template <int N>
```

**Template Template Parameter**
```cpp
template <template <typename> class C>
```

**Component Breakdown**

| Kind | Example |
|------|---------|
| Type | `typename T`, `class T` |
| Non-type | `int N`, `bool B` |
| Template template | `template <typename> class C` |

**Syntax Rules**
- `typename` and `class` are equivalent for type parameters .
- Non-type parameters must be constant expressions.
- Parameter packs use `...` (C++11) .

**Constraints and Limitations**
- Non-type parameters must be known at compile time.
- Template template parameters have matching constraints.

### Annotated Code Examples

**Example 1: Non-type parameter**

```cpp
#include <iostream>

template <int N>
struct Array {
    int data[N];
    static constexpr int size = N;
};

int main() {
    Array<5> a;
    std::cout << a.size << '\n';
}
```

**Expected Output**
```
5
```

**Why this output?**  
`N` is a non-type template parameter; `Array<5>` has `size = 5`.

### Real-World Cases

- **`std::array<T, N>`** – fixed-size array with non-type `N`.
- **`std::integral_constant<T, v>`** – wraps a non-type value.
- **Policy-based design** – template template parameters.

## 5. Template Arguments

### Definitions

**Core Definition**
Template arguments are the actual types, values, or templates supplied to a template to produce a specialization.

**Technical Definition**
Template arguments are substituted for template parameters to obtain a specialization . For function templates, arguments can be **deduced** from the function arguments; for class templates (since C++17), they can be deduced from constructor arguments (CTAD). Explicit arguments are provided in angle brackets: `max<int>(a, b)`.

**Beginner-Friendly Explanation**
Template arguments are the **values you fill in**. For `template <typename T>`, passing `int` makes `T = int`.

### Purposes

- To select a specific specialization.
- To control template behavior.
- To enable deduction (implicit arguments).

### Syntax Rules and Structure

**Explicit Arguments**
```cpp
max<int>(a, b);
Box<double> b(3.14);
```

**Deduced Arguments**
```cpp
max(a, b);           // T deduced
Box b(3.14);         // T deduced (C++17)
```

**Component Breakdown**

| Form | Meaning |
|------|---------|
| `<T>` | Explicit template argument. |
| Deduction | Compiler infers arguments. |

**Syntax Rules**
- Explicit arguments must match parameter kinds.
- Deduction applies to function templates and (C++17) class templates .
- Arguments can be defaulted.

**Constraints and Limitations**
- Deduction may fail (ambiguous or unsupported).
- Explicit arguments must satisfy constraints (C++20).

### Annotated Code Examples

**Example 1: Explicit vs. deduced**

```cpp
#include <iostream>

template <typename T>
T add(T a, T b) { return a + b; }

int main() {
    std::cout << add(1, 2) << '\n';        // deduced: T = int
    std::cout << add<double>(1, 2) << '\n'; // explicit: T = double
}
```

**Expected Output**
```
3
3
```

**Why this output?**  
The first call deduces `T = int`; the second explicitly sets `T = double` (arguments converted).

### Real-World Cases

- **`std::vector<int>`** – explicit type argument.
- **`std::make_pair(1, 2.0)`** – deduced pair type.

## 6. Template Instantiation

### Definitions

**Core Definition**
Template instantiation is the process by which the compiler generates a concrete class or function from a template for a specific set of template arguments.

**Technical Definition**
Instantiation occurs when a specialization is referenced in a context requiring a complete type or function definition . The compiler substitutes the template arguments for the parameters and compiles the resulting code. Instantiation may be **implicit** (triggered by use) or **explicit** (requested by the programmer). Class template instantiation does not instantiate member functions unless used . Identical instantiations from different translation units are merged at link time .

**Beginner-Friendly Explanation**
Instantiation is the compiler **filling in the blanks and generating real code**. When you write `max(3, 7)`, the compiler instantiates `max<int>`.

### Purposes

- To generate concrete code from templates.
- To control when and where code is generated.
- To support separate compilation (via explicit instantiation).

### Syntax Rules and Structure

Instantiation is not usually written explicitly; it is triggered by use.

**Component Breakdown**

| Kind | Trigger |
|------|---------|
| Implicit | Use of the template. |
| Explicit | `template` declaration. |

**Syntax Rules**
- Implicit instantiation occurs on use.
- Explicit instantiation is requested with the `template` keyword.
- Definitions must be visible for implicit instantiation.

**Constraints and Limitations**
- Class template members are instantiated only when used .
- Instantiation errors appear at the point of use.

### Annotated Code Examples

**Example 1: Implicit instantiation**

```cpp
#include <iostream>

template <typename T>
T square(T x) { return x * x; }

int main() {
    std::cout << square(5) << '\n';   // instantiates square<int>
}
```

**Expected Output**
```
25
```

**Why this output?**  
The call triggers implicit instantiation of `square<int>`.

### Real-World Cases

- **STL usage** – every `std::vector<int>` use instantiates members.
- **Header-only libraries** – rely on implicit instantiation.

## 7. Implicit Instantiation

### Definitions

**Core Definition**
Implicit instantiation is the automatic generation of a specialization when a template is used, without an explicit request.

**Technical Definition**
If a specialization does not already exist, the compiler implicitly instantiates it when it is referenced in a context requiring a complete type or definition . For class templates, only used members are instantiated .

**Beginner-Friendly Explanation**
Implicit instantiation is the compiler **doing it automatically** when you use a template.

### Purposes

- To generate code on demand.
- To avoid unnecessary instantiation.
- To support natural template usage.

### Syntax Rules and Structure

Triggered by use:
```cpp
max(3, 7);          // implicit instantiation
std::vector<int> v; // implicit instantiation of vector<int> (as needed)
```

**Syntax Rules**
- Requires the template definition to be visible.
- Class template members instantiated only when used .

**Constraints and Limitations**
- Errors surface at use sites.
- Can cause code bloat.

### Annotated Code Examples

**Example 1: Only used members instantiated**

```cpp
template <typename T>
struct S {
    void used() {}
    void unused() { T::nonexistent(); }   // never instantiated if not called
};

int main() {
    S<int> s;
    s.used();   // OK: unused() not instantiated
}
```

**Expected Output**  
(Compiles; `unused` is never instantiated.)

**Why this output?**  
Class template member functions are instantiated only when used .

### Real-World Cases

- **STL containers** – only used member functions are instantiated.
- **Header-only libraries** – implicit instantiation on use.

## 8. Explicit Instantiation

### Definitions

**Core Definition**
Explicit instantiation is a request by the programmer to generate a specific specialization of a template, without relying on implicit use.

**Technical Definition**
Explicit instantiation uses the `template` keyword followed by a declaration (not definition) with the template arguments . For functions: `template float twice<float>(float);`. For classes: `template class Array<char>;` (instantiates all members). For members: `template int Array<char>::GetSize();` .

**Beginner-Friendly Explanation**
Explicit instantiation is you **telling the compiler to generate that version now**, even if it isn't used in this file. It's useful for libraries.

### Purposes

- To control where instantiations are generated.
- To reduce compile times in large projects.
- To ensure specific specializations exist.

### Syntax Rules and Structure

**Function**
```cpp
template return_type function<args>(params);
```

**Class**
```cpp
template class ClassName<args>;
```

**Component Breakdown**

| Form | Effect |
|------|--------|
| `template class X<int>;` | Instantiates all members. |
| `template int f<int>(int);` | Instantiates the function. |

**Syntax Rules**
- The `template` keyword precedes a declaration (not definition) .
- Template arguments may be omitted if deducible .
- Class explicit instantiation instantiates all members .

**Constraints and Limitations**
- Explicit instantiation definitions must be visible.
- Cannot explicitly instantiate after explicit specialization.

### Annotated Code Examples

**Example 1: Explicit instantiation**

```cpp
// header
template <typename T>
T twice(T x) { return 2 * x; }

// source
template int twice<int>(int);   // explicit instantiation
```

**Expected Output**  
(Generates `twice<int>`.)

**Why this is used?**  
The explicit instantiation forces code generation in this translation unit.

### Real-World Cases

- **Library headers** – explicit instantiation in `.cpp` files.
- **Reducing compile times** – instantiate once, link everywhere.

## 9. Template Specialization

### Definitions

**Core Definition**
Template specialization is the provision of a **custom implementation** for a specific set of template arguments, overriding the primary template.

**Technical Definition**
Specializations may be **explicit** (full specialization) or **partial** (for class/variable templates only) . Full specialization provides a complete implementation for a specific argument list. Partial specialization provides a pattern for a subset of arguments (class templates and variable templates only) .

**Beginner-Friendly Explanation**
Specialization is **customizing a template for a particular type**. For example, you might specialize `print<T>` for `bool` to print `"true"`/`"false"` instead of `1`/`0`.

### Purposes

- To optimize for specific types.
- To provide correct behavior for types with special semantics.
- To customize library templates.

### Syntax Rules and Structure

**Full Specialization**
```cpp
template <>
struct X<int> { /* custom */ };
```

**Partial Specialization**
```cpp
template <typename T>
struct X<T*> { /* custom for pointers */ };
```

**Component Breakdown**

| Kind | Syntax |
|------|--------|
| Full | `template <> class X<int> { ... };` |
| Partial | `template <typename T> class X<T*> { ... };` |

**Syntax Rules**
- Full specialization uses `template <>`.
- Partial specialization uses a template parameter list with a pattern.
- Partial specialization is only for class templates and variable templates .

**Constraints and Limitations**
- Function templates cannot be partially specialized (use overloading) .
- Specializations must be visible before first use.

### Annotated Code Examples

**Example 1: Full specialization**

```cpp
#include <iostream>

template <typename T>
struct Printer {
    static void print(T value) { std::cout << value << '\n'; }
};

template <>
struct Printer<bool> {
    static void print(bool value) { std::cout << (value ? "true" : "false") << '\n'; }
};

int main() {
    Printer<int>::print(42);
    Printer<bool>::print(true);
}
```

**Expected Output**
```
42
true
```

**Why this output?**  
The full specialization for `bool` prints `"true"` instead of `1`.

### Real-World Cases

- **`std::hash<T>`** – specializations for different types.
- **`std::numeric_limits<T>`** – customized for each type.
- **Type traits** – specializations for categories.

## 10. Full Specialization

### Definitions

**Core Definition**
Full specialization (explicit specialization) provides a complete implementation of a template for a specific, fully specified set of template arguments.

**Technical Definition**
A full specialization is declared with `template <>` followed by the class/function definition with all arguments specified . It overrides the primary template for that exact argument list. Full specializations are allowed for class, variable, and function templates .

**Beginner-Friendly Explanation**
Full specialization is **replacing the template entirely for one specific type**. No template parameters remain.

### Purposes

- To provide a completely custom implementation for a specific type.
- To handle types with special requirements.
- To optimize specific cases.

### Syntax Rules and Structure

**General Syntax**
```cpp
template <>
class X<int> { ... };
```

**Component Breakdown**

| Component | Description |
|-----------|-------------|
| `template <>` | Indicates full specialization. |
| `X<int>` | Specific arguments. |

**Syntax Rules**
- All template arguments must be specified.
- Must be declared before first use.
- Can specialize class, function, or variable templates .

**Constraints and Limitations**
- Cannot be used with partial argument lists.
- Must match the primary template's interface.

### Annotated Code Examples

**Example 1: Full function specialization**

```cpp
#include <iostream>
#include <string>

template <typename T>
T add(T a, T b) { return a + b; }

template <>
std::string add<std::string>(std::string a, std::string b) {
    return a + " " + b;
}

int main() {
    std::cout << add(1, 2) << '\n';
    std::cout << add<std::string>("hello", "world") << '\n';
}
```

**Expected Output**
```
3
hello world
```

**Why this output?**  
The full specialization for `std::string` inserts a space.

### Real-World Cases

- **`std::hash<std::string>`** – custom hashing.
- **`std::swap`** – optimized swaps for specific types.

## 11. Partial Specialization

### Definitions

**Core Definition**
Partial specialization provides a template implementation for a **subset of template arguments** that match a pattern, rather than a fully specified list.

**Technical Definition**
Partial specialization is allowed only for **class templates and variable templates** (C++14) . It uses a template parameter list with a pattern (e.g., `T*`, `T&`, `std::vector<T>`) and provides a customized implementation when the arguments match that pattern.

**Beginner-Friendly Explanation**
Partial specialization is **customizing for a family of types**, like “all pointers” or “all `std::vector`s.”

### Purposes

- To customize behavior for categories of types.
- To optimize for pointer types, references, or template instantiations.
- To implement type traits.

### Syntax Rules and Structure

**General Syntax**
```cpp
template <typename T>
class X<T*> { ... };   // specialization for all pointer types
```

**Component Breakdown**

| Pattern | Meaning |
|---------|---------|
| `T*` | All pointers. |
| `T&` | All references. |
| `std::vector<T>` | All vectors. |

**Syntax Rules**
- Only for class and variable templates .
- The pattern must be more specialized than the primary template.
- Template parameters are deduced from the pattern.

**Constraints and Limitations**
- Function templates cannot be partially specialized (use overloading) .
- Ambiguity can arise with multiple matching partial specializations.

### Annotated Code Examples

**Example 1: Partial specialization for pointers**

```cpp
#include <iostream>

template <typename T>
struct TypeInfo {
    static void print() { std::cout << "general\n"; }
};

template <typename T>
struct TypeInfo<T*> {
    static void print() { std::cout << "pointer\n"; }
};

int main() {
    TypeInfo<int>::print();
    TypeInfo<int*>::print();
}
```

**Expected Output**
```
general
pointer
```

**Why this output?**  
The partial specialization `TypeInfo<T*>` matches pointer types.

### Real-World Cases

- **`std::is_pointer<T>`** – partial specialization for `T*`.
- **`std::remove_reference<T>`** – partial specialization for `T&`.
- **Smart pointer traits** – customizing for pointer categories.

## 12. Template Best Practices

### Definitions

**Core Definition**
Template best practices are guidelines for writing templates that are correct, readable, efficient, and maintainable.

**Technical Definition**
The C++ Core Guidelines provide template rules (T.1–T.13, T.40–T.83). Key principles: use templates to express algorithms that work on many argument types (T.2); use function templates to deduce argument types (T.10); specify concepts for template parameters (T.10, C++20); use `auto` and `decltype` carefully; avoid over-templating non-generic code ; and use `std::function` or templates appropriately for callbacks . Templates should be constrained with concepts where possible to improve error messages and express requirements.

**Beginner-Friendly Explanation**
Best practices for templates are simple: **use templates for truly generic code**, **constrain them with concepts**, **don't over-template**, **keep error messages readable**, and **prefer concrete types when only one type is used**.

### Key Guidelines (Summary Table)

| Guideline | Summary | Recommendation |
|-----------|---------|----------------|
| **Use for generic code** | Templates are for families of types. | Don't template one-off functions. |
| **Constrain with concepts** | Concepts (C++20) express requirements. | `template <std::integral T>`. |
| **Deduce arguments** | Let the compiler deduce. | `max(a, b)` not `max<int>(a, b)`. |
| **Avoid over-templating** | Over-templating hurts readability and errors . | Use concrete types when possible. |
| **Header definitions** | Templates typically belong in headers . | Header-only libraries. |
| **Explicit instantiation** | Control where code is generated. | Use in libraries. |
| **Specialization** | Use full/partial specialization carefully. | Document customizations. |

### Annotated Code Examples

**Example 1: Constrained template (C++20)**

```cpp
#include <iostream>
#include <concepts>

template <std::integral T>
T add(T a, T b) {
    return a + b;
}

int main() {
    std::cout << add(1, 2) << '\n';
    // add(1.5, 2.5);   // error: double is not integral
}
```

**Expected Output**
```
3
```

**Why this is best practice?**  
The `std::integral` concept clearly expresses the requirement and produces a readable error at the call site .

- **Standard library** – templates constrained with concepts in C++20.
- **Code review** – concepts and clear constraints are preferred.
- **Static analysis** – tools check template usage.
