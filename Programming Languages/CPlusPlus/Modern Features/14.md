# C++14 Features — Comprehensive Programming Cheat Sheet

---

## Topic Overview

### Definitions

**Core Definition**
C++14 (ISO/IEC 14882:2014) is a minor revision of the C++ standard that extends C++11 with language and library refinements—most notably generic lambdas, return type deduction, variable templates, relaxed `constexpr`, binary literals, digit separators, and several new standard library utilities.

**Technical Definition**
C++14 was published on 15 December 2014. It is a "bug-fix and refinement" release relative to C++11, but it introduced several impactful features: generic lambda expressions (N3649), return type deduction for normal functions (N3638), variable templates, relaxed `constexpr` constraints (N3652), binary literals (N3472), digit separators (N3781), and library additions including `std::make_unique`, `std::shared_timed_mutex`, `std::integer_sequence`, `std::exchange`, and `std::quoted`. The standard also removed the C++11 restriction that aggregate types could not contain non-static data members with default member initializers.

**Beginner-Friendly Explanation**
C++14 is the "polish" release after the big C++11 overhaul. It didn't change the world, but it made everyday C++ much nicer: you can write generic lambdas, let functions deduce their return types, use binary literals like `0b1010`, and finally get `std::make_unique` to match `std::make_shared`.

### Key Characteristics

- **Generic lambdas** – lambda parameters can use `auto`, making the lambda’s `operator()` an implicit function template.
- **Return type deduction** – normal functions can use `auto` (and `decltype(auto)`) without a trailing return type.
- **Variable templates** – variables and static data members can be templated.
- **Relaxed `constexpr`** – nearly all statements are allowed in `constexpr` function bodies, including loops and local variables.
- **Binary literals and digit separators** – `0b1010` and `1'000'000` improve readability.
- **Library utilities** – `std::make_unique`, `std::shared_timed_mutex`, `std::integer_sequence`, `std::exchange`, and `std::quoted` fill important gaps.

### Prerequisites

- Basic C++ syntax (functions, templates, lambdas).
- Familiarity with C++11 features (`auto`, lambdas, move semantics, `constexpr`).
- Understanding of the standard library (containers, smart pointers, threading).
- Knowledge of compile-time programming concepts.

### Related Programming Areas

- **Generic programming** – generic lambdas, variable templates, `decltype(auto)`.
- **Compile-time computation** – relaxed `constexpr`.
- **Concurrency** – `std::shared_timed_mutex` for reader-writer locks.
- **I/O formatting** – `std::quoted` for CSV/XML-like data.
- **Utility programming** – `std::exchange`, `std::integer_sequence`.

## 1. Generic Lambdas

### Definitions

**Core Definition**
A generic lambda is a lambda expression whose parameters are declared with `auto`, making the lambda’s `operator()` an implicit function template that can accept arguments of different types.

**Technical Definition**
C++14 allows `auto` in lambda parameter lists (N3649). The compiler generates a closure type whose `operator()` is a template; each distinct argument type used at a call site instantiates a separate `operator()` specialization. A generic lambda is not itself a template and is not of polymorphic type, but its call operator is templated.

**Beginner-Friendly Explanation**
A generic lambda is a lambda that doesn’t care about the exact types of its parameters. You write `[](auto a, auto b) { return a + b; }` and it works for `int`, `double`, `std::string`, or any type that supports `+`.

### Purposes

- To avoid writing separate lambdas for each concrete type.
- To express type-independent logic (comparison, arithmetic, printing) once.
- To use a single lambda with heterogeneous containers.
- To reduce boilerplate in generic algorithms.

### Syntax Rules and Structure

**General Syntax**
```cpp
auto lambda = [](auto param1, auto param2) { /* ... */ };
```

**Component Breakdown**

| Component | Description |
|-----------|-------------|
| `auto` | Type placeholder for a parameter. |
| `operator()` | Implicitly a template member function. |

**Syntax Rules**
- At least one parameter must use `auto` to make the lambda generic.
- Parameters can mix `auto` and concrete types.
- `auto&&` enables forwarding references inside the lambda.
- Captures work as in non-generic lambdas.

**Constraints and Limitations**
- Each instantiation generates a separate `operator()` specialization, increasing code size.
- The lambda is not a template itself; it cannot be explicitly specialized.
- The closure type is unique per lambda expression (cannot be named).

### Annotated Code Examples

**Example 1: Basic generic lambda**

```cpp
#include <iostream>

int main() {
    auto identity = [](auto x) { return x; };
    std::cout << identity(42) << '\n';        // int
    std::cout << identity(3.14) << '\n';      // double
}
```

**Expected Output**
```
42
3.14
```

**Why this output?**  
The lambda’s `operator()` is a template; `identity(42)` instantiates it with `T = int`, and `identity(3.14)` instantiates it with `T = double`.

**Example 2: Generic lambda with STL algorithms**

```cpp
#include <algorithm>
#include <vector>
#include <iostream>

int main() {
    std::vector<int> v1 = {5, 1, 4, 2};
    std::vector<double> v2 = {3.1, 2.7, 8.5};

    auto gt = [](auto a, auto b) { return a > b; };
    std::sort(v1.begin(), v1.end(), gt);
    std::sort(v2.begin(), v2.end(), gt);

    for (auto x : v1) std::cout << x << ' ';
    std::cout << '\n';
    for (auto x : v2) std::cout << x << ' ';
}
```

**Expected Output**
```
5 4 2 1
8.5 3.1 2.7
```

**Why this output?**  
A single generic lambda provides the descending comparator for both `int` and `double` vectors, which would have required two separate lambdas in C++11.

### Real-World Cases

- **Heterogeneous containers** – applying the same operation to `vector<int>` and `vector<double>`.
- **Generic logging** – `auto log = [](auto const& x) { std::cout << x; };`.
- **Perfect-forwarding wrappers** – `[](auto&&... args) { return f(std::forward<decltype(args)>(args)...); }`.

## 2. Return Type Deduction

### Definitions

**Core Definition**
Return type deduction allows a normal function (not just a lambda) to omit its return type and have the compiler deduce it from the `return` statements.

**Technical Definition**
C++14 extends the C++11 lambda return type deduction to all functions (N3638). If a function declaration uses `auto` without a trailing return type, the return type is deduced from the `return` expressions; all `return` statements must yield the same type. The special form `decltype(auto)` deduces the type using `decltype` rules, preserving references.

**Beginner-Friendly Explanation**
Instead of writing `int add(int a, int b)`, you can write `auto add(int a, int b) { return a + b; }` and the compiler figures out the return type from the `return` statement.

### Purposes

- To reduce verbosity when the return type is obvious.
- To make function templates easier to write (no trailing return type needed).
- To use `decltype(auto)` to preserve reference and value categories in forwarding functions.
- To avoid maintaining return type annotations.

### Syntax Rules and Structure

**General Syntax**
```cpp
auto function_name(parameters) { return expression; }
decltype(auto) function_name(parameters) { return expression; }
```

**Component Breakdown**

| Form | Deduction Rule |
|------|----------------|
| `auto` | Deduces by value (drops references and top-level `const`). |
| `decltype(auto)` | Deduces using `decltype` rules (preserves references). |

**Syntax Rules**
- All `return` statements in a function with `auto` return type must deduce the same type.
- The function body must be visible before the function is used (for `auto` return type).
- `decltype(auto)` is primarily useful for forwarding functions and wrappers.

**Constraints and Limitations**
- Recursive functions work as long as a `return` precedes the recursive call.
- `auto` return type cannot be used for virtual functions.

### Annotated Code Examples

**Example 1: `auto` return type**

```cpp
#include <iostream>

auto add(int a, int b) { return a + b; }
auto greet() { return std::string("hello"); }

int main() {
    std::cout << add(2, 3) << '\n';        // 5
    std::cout << greet() << '\n';          // hello
}
```

**Expected Output**
```
5
hello
```

**Why this output?**  
`add` deduces `int`; `greet` deduces `std::string` from the returned expression.

**Example 2: `decltype(auto)` for reference preservation**

```cpp
#include <iostream>

int& get(int& x) { return x; }

decltype(auto) forward(int& x) { return get(x); }  // returns int&

int main() {
    int n = 10;
    forward(n) = 99;
    std::cout << n << '\n';                // 99
}
```

**Expected Output**
```
99
```

**Why this output?**  
`decltype(auto)` preserves the reference return type of `get`, so `forward(n) = 99` modifies `n`.

### Real-World Cases

- **Generic wrappers** – `template<class F> auto call(F f) { return f(); }`.
- **Forwarding functions** – `decltype(auto)` for perfect forwarding.
- **Reducing boilerplate** – simple accessors and arithmetic helpers.

## 3. Variable Templates

### Definitions

**Core Definition**
A variable template defines a family of variables or static data members parameterized by a template parameter list.

**Technical Definition**
C++14 introduced variable templates. A variable template is introduced by a `template` declaration at namespace scope, where the declaration declares a variable. The declared variable name becomes a template name. A variable instantiated from a variable template is called an *instantiated variable*; a static data member instantiated from a static data member template is an *instantiated static data member*.

**Beginner-Friendly Explanation**
A variable template is like a function template but for variables. You can write `template<class T> constexpr T pi = T(3.14159);` and then use `pi<float>` or `pi<double>`.

### Purposes

- To define parameterized constants (e.g., `pi<T>`, `zero<T>`).
- To replace class-template static data members or `constexpr` function templates.
- To simplify type-dependent constant expressions.
- To support generic numeric programming.

### Syntax Rules and Structure

**General Syntax**
```cpp
template< parameter-list >
variable-declaration;
```

**Component Breakdown**

| Component | Description |
|-----------|-------------|
| `template<...>` | Template parameter list. |
| `variable-declaration` | The variable to be templated. |

**Syntax Rules**
- Variable templates can be declared at namespace scope.
- They can be `constexpr`, `inline`, or both.
- They cannot be used as template template arguments.

**Constraints and Limitations**
- Variable templates require C++14.
- Before C++14, parameterized variables were typically implemented as static data members of class templates or as `constexpr` function templates returning the desired value.

### Annotated Code Example

```cpp
#include <iostream>

template<class T>
constexpr T pi = T(3.1415926535897932385L);

template<class T>
T circular_area(T r) {
    return pi<T> * r * r;
}

int main() {
    std::cout << circular_area(2.0f) << '\n';   // float
    std::cout << circular_area(2.0) << '\n';    // double
}
```

**Expected Output**
```
12.5664
12.5664
```

**Why this output?**  
`pi<float>` and `pi<double>` are distinct instantiations of the variable template; the appropriate precision is used for each call.

### Real-World Cases

- **Mathematical constants** – `pi<T>`, `e<T>`, `sqrt2<T>`.
- **Type traits** – `is_signed_v<T>` (before C++17, variable templates were the only way to write `_v`-style traits).
- **Generic configuration** – `default_value<T>`.

## 4. `constexpr` Improvements

### Definitions

**Core Definition**
C++14 relaxed the rules for `constexpr` function bodies, allowing nearly all statements—including loops, local variables, and conditionals—to be used in constant evaluation.

**Technical Definition**
In C++11, `constexpr` function bodies were restricted to a single `return` statement (plus limited declarations). C++14 (N3652) allows nearly all statements in `constexpr` functions, including local variable declarations, `if`/`switch`, all looping constructs (`for`, `while`, `do-while`, range-based `for`), and mutation of objects whose lifetime began within the constant expression evaluation. `goto` remains disallowed.

**Beginner-Friendly Explanation**
Before C++14, `constexpr` functions could only contain a single `return`. Now they can contain almost anything a normal function can—loops, variables, `if` statements—as long as the function can still be evaluated at compile time when needed.

### Purposes

- To write idiomatic compile-time code without recursion or single-expression tricks.
- To move complex computations from runtime to compile time.
- To allow `constexpr` functions to use local variables and control flow.
- To improve compile-time and runtime performance (loops are faster than recursion).

### Syntax Rules and Structure

**General Syntax**
```cpp
constexpr ReturnType function_name(parameters) {
    // nearly any statements, including loops and local variables
}
```

**Component Breakdown**

| Feature | C++11 | C++14 |
|---------|-------|-------|
| Local variables | Limited | Allowed |
| `if`/`switch` | No | Allowed |
| Loops | No | Allowed (except `goto`) |
| Multiple `return` | No | Allowed (same type) |

**Syntax Rules**
- The function must still be valid for constant evaluation for at least one set of arguments.
- `constexpr` functions are implicitly `inline`.
- Local variables in `constexpr` functions are allowed if their lifetime begins within the constant evaluation.

**Constraints and Limitations**
- `goto` is still disallowed.
- Some operations (e.g., `reinterpret_cast`, `dynamic_cast`) are not allowed in constant expressions.

### Annotated Code Example

```cpp
#include <iostream>

constexpr int factorial(int n) {
    int result = 1;
    for (int i = 2; i <= n; ++i) {
        result *= i;
    }
    return result;
}

int main() {
    constexpr int f5 = factorial(5);       // compile-time
    std::cout << f5 << '\n';               // 120
}
```

**Expected Output**
```
120
```

**Why this output?**  
The loop is allowed in C++14 `constexpr` functions, so `factorial(5)` is evaluated at compile time.

### Real-World Cases

- **Compile-time tables** – generating lookup tables.
- **Mathematical functions** – `constexpr` implementations of `pow`, `sqrt`.
- **Type traits** – complex `constexpr` trait computations.

## 5. Binary Literals

### Definitions

**Core Definition**
A binary literal is an integer literal written in base 2, prefixed with `0b` or `0B`.

**Technical Definition**
C++14 added binary integer literals (N3472). The syntax is `0b` or `0B` followed by one or more binary digits (`0` or `1`). Binary literals work with digit separators and user-defined literal suffixes.

**Beginner-Friendly Explanation**
You can now write binary numbers directly in code: `0b1010` is the same as `10` in decimal.

### Purposes

- To write bitmasks and hardware registers in their natural binary form.
- To improve readability of low-level code.
- To combine with digit separators for grouping bits.

### Syntax Rules and Structure

**General Syntax**
```cpp
int x = 0b1010;          // binary literal
int y = 0B1111'0000;     // binary with digit separator
```

**Component Breakdown**

| Prefix | Meaning |
|--------|---------|
| `0b` / `0B` | Binary literal. |

**Syntax Rules**
- Only digits `0` and `1` are allowed after the prefix.
- Digit separators (`'`) can be used.
- User-defined literal suffixes are allowed.

**Constraints and Limitations**
- Binary literals are not available before C++14.

### Annotated Code Example

```cpp
#include <iostream>

int main() {
    int a = 0b1010;                        // 10
    int b = 0b1111'0000;                   // 240
    std::cout << a << ' ' << b << '\n';
}
```

**Expected Output**
```
10 240
```

**Why this output?**  
`0b1010` is binary for 10; `0b1111'0000` is binary for 240, with a digit separator for readability.

### Real-World Cases

- **Bitmasks** – `0b0000'1111` for flags.
- **Hardware registers** – specifying bit patterns directly.
- **Protocol constants** – binary headers and flags.

## 6. Digit Separators

### Definitions

**Core Definition**
A digit separator is a single quote (`'`) that can be inserted between digits of a numeric literal to improve readability without affecting the value.

**Technical Definition**
C++14 introduced digit separators (N3781). The single quote can be used to group digits in integer and floating-point literals of any base. It is ignored by the compiler and has no effect on the value. For binary literals, groups of four or eight bits are conventional.

**Beginner-Friendly Explanation**
Digit separators let you write `1'000'000` instead of `1000000`, making large numbers easier to read.

### Purposes

- To make large numeric literals readable.
- To group bits in binary literals (nibbles or bytes).
- To group hex digits for clarity.
- To improve code maintainability.

### Syntax Rules and Structure

**General Syntax**
```cpp
int million = 1'000'000;
int hex = 0xDEAD'BEEF;
int binary = 0b1111'0000;
```

**Component Breakdown**

| Separator | Effect |
|-----------|--------|
| `'` | Ignored by the compiler; groups digits. |

**Syntax Rules**
- The separator can appear between any two digits.
- It works with decimal, hexadecimal, binary, and octal literals.
- It works with floating-point literals.

**Constraints and Limitations**
- The separator cannot appear at the beginning or end of a literal, or adjacent to another separator.

### Annotated Code Example

```cpp
#include <iostream>

int main() {
    int million = 1'000'000;
    int color = 0xFF'00'00;
    int ascii_A = 0b100'0001;
    std::cout << million << ' ' << color << ' ' << ascii_A << '\n';
}
```

**Expected Output**
```
1000000 16711680 65
```

**Why this output?**  
Digit separators are ignored; `1'000'000` is `1000000`; `0xFF'00'00` is `0xFF0000`; `0b100'0001` is binary for 65 (ASCII 'A').

### Real-World Cases

- **Large constants** – timestamps, file sizes.
- **Bitmasks** – grouping bits into bytes.
- **Hexadecimal constants** – grouping bytes in colour codes.

## 7. `std::make_unique`

### Definitions

**Core Definition**
`std::make_unique` is a factory function that constructs an object of type `T` and wraps it in a `std::unique_ptr`.

**Technical Definition**
Defined in `<memory>` since C++14, `std::make_unique<T>(args...)` constructs a non-array object `T` with the forwarded arguments and returns `unique_ptr<T>`. An overload for arrays of unknown bound takes a size and value-initializes the elements. Construction of arrays of known bound is disallowed.

**Beginner-Friendly Explanation**
`std::make_unique` is the `unique_ptr` counterpart to `std::make_shared`. It creates the object and the `unique_ptr` in one step, avoiding the need to write `new` yourself.

### Purposes

- To eliminate raw `new` in `unique_ptr` creation.
- To avoid spelling `T` twice (`std::unique_ptr<T>{new T{...}}`).
- To provide exception safety.
- To complement `std::make_shared`.

### Syntax Rules and Structure

**General Syntax**
```cpp
auto p = std::make_unique<T>(args...);
auto arr = std::make_unique<T[]>(n);
```

**Component Breakdown**

| Overload | Purpose |
|----------|---------|
| `make_unique<T>(args...)` | Non-array type. |
| `make_unique<T[]>(n)` | Array of unknown bound, value-initialized. |

**Syntax Rules**
- `T` is deduced from the template argument.
- Array overloads require `T[]` with a size.
- Known-bound arrays are rejected at compile time.

**Constraints and Limitations**
- Requires C++14 or later.
- Does not support custom deleters (use the `unique_ptr` constructor for that).

### Annotated Code Example

```cpp
#include <memory>
#include <iostream>

struct Point { int x, y; };

int main() {
    auto p = std::make_unique<Point>(Point{1, 2});
    std::cout << p->x << ',' << p->y << '\n';

    auto arr = std::make_unique<int[]>(3);
    arr[0] = 10;
    std::cout << arr[0] << '\n';
}
```

**Expected Output**
```
1,2
10
```

**Why this output?**  
`make_unique<Point>` constructs a `Point` and wraps it; `make_unique<int[]>` creates a value-initialized array of three ints.

### Real-World Cases

- **Factory functions** – returning `unique_ptr` without raw `new`.
- **Pimpl idiom** – `std::make_unique<Impl>()`.
- **Array ownership** – `std::make_unique<int[]>(size)`.

## 8. `std::shared_timed_mutex`

### Definitions

**Core Definition**
`std::shared_timed_mutex` is a synchronization primitive that provides both exclusive (write) and shared (read) ownership modes, with timeout support.

**Technical Definition**
Defined in `<shared_mutex>` since C++14, `shared_timed_mutex` satisfies the *SharedTimedMutex* requirements. It provides exclusive locking (`lock`, `try_lock`, `try_lock_for`, `try_lock_until`) and shared locking (`lock_shared`, `try_lock_shared`, `try_lock_shared_for`, `try_lock_shared_until`). Multiple readers may hold shared ownership simultaneously, but a writer requires exclusive ownership.

**Beginner-Friendly Explanation**
A `shared_timed_mutex` is a reader-writer lock with timeouts. Many readers can read at the same time, but a writer must have exclusive access.

### Purposes

- To protect data that is read frequently and written rarely.
- To allow concurrent readers while ensuring exclusive writer access.
- To support timeouts on lock acquisition.
- To implement reader-writer locks in the standard library.

### Syntax Rules and Structure

**General Syntax**
```cpp
std::shared_timed_mutex m;
std::shared_lock<std::shared_timed_mutex> read_lock(m);
std::unique_lock<std::shared_timed_mutex> write_lock(m);
```

**Component Breakdown**

| Lock Type | Ownership | Holder |
|-----------|-----------|--------|
| `shared_lock` | Shared (read) | Multiple threads |
| `unique_lock` | Exclusive (write) | One thread |

**Syntax Rules**
- Shared ownership is acquired via `lock_shared()` or `shared_lock`.
- Exclusive ownership is acquired via `lock()` or `unique_lock`.
- Timeout versions return `bool` indicating success.

**Constraints and Limitations**
- Requires C++14 or later.
- Reader-writer locks have more overhead than plain mutexes; use only when read-heavy.

### Annotated Code Example

```cpp
#include <iostream>
#include <shared_mutex>
#include <thread>
#include <vector>

std::shared_timed_mutex mtx;
int shared_data = 0;

void reader(int id) {
    std::shared_lock<std::shared_timed_mutex> lock(mtx);
    std::cout << "Reader " << id << ": " << shared_data << '\n';
}

void writer() {
    std::unique_lock<std::shared_timed_mutex> lock(mtx);
    ++shared_data;
}

int main() {
    std::thread w(writer);
    w.join();
    std::thread r1(reader, 1), r2(reader, 2);
    r1.join();
    r2.join();
}
```

**Expected Output**
```
Reader 1: 1
Reader 2: 1
```

**Why this output?**  
The writer increments `shared_data` under exclusive lock; the two readers acquire shared locks and both see the updated value.

### Real-World Cases

- **Caches** – many readers, occasional updates.
- **Configuration data** – read by many threads, reloaded rarely.
- **Symbol tables** – concurrent lookups with rare insertions.

## 9. `std::integer_sequence`

### Definitions

**Core Definition**
`std::integer_sequence` is a class template that represents a compile-time sequence of integers of a specified type.

**Technical Definition**
Defined in `<utility>` since C++14, `std::integer_sequence<T, Ints...>` holds a non-type template parameter pack of integers of type `T`. When used as an argument to a function template, the `Ints` pack can be deduced and used in pack expansion. Helper aliases `index_sequence`, `make_integer_sequence`, and `make_index_sequence` simplify common use cases.

**Beginner-Friendly Explanation**
`std::integer_sequence` is a compile-time list of numbers. It is mainly used to “unpack” tuples and other variadic templates by generating an index sequence `0, 1, 2, ..., N-1`.

### Purposes

- To generate compile-time index sequences for pack expansion.
- To implement tuple-like utilities and generic function application.
- To simplify variadic template programming.
- To replace hand-written recursive index generators.

### Syntax Rules and Structure

**General Syntax**
```cpp
std::integer_sequence<int, 0, 1, 2> seq;
std::index_sequence<0, 1, 2> idx;          // alias for size_t
std::make_index_sequence<3> idx;            // 0, 1, 2
```

**Component Breakdown**

| Component | Description |
|-----------|-------------|
| `integer_sequence<T, Ints...>` | Sequence of `T` values. |
| `index_sequence<Ints...>` | Alias for `integer_sequence<size_t, Ints...>`. |
| `make_integer_sequence<T, N>` | `0, 1, ..., N-1`. |
| `make_index_sequence<N>` | `index_sequence` for `0..N-1`. |

**Syntax Rules**
- `size()` returns the number of elements (`sizeof...(Ints)`).
- `value_type` is `T`.
- Used with function templates to deduce `Ints` via pack expansion.

**Constraints and Limitations**
- Requires C++14 or later.
- Compile-time only; no runtime sequence container.

### Annotated Code Example

```cpp
#include <iostream>
#include <utility>
#include <tuple>

template<class Tuple, std::size_t... I>
void print_tuple_impl(const Tuple& t, std::index_sequence<I...>) {
    ((std::cout << (I == 0 ? "" : " ") << std::get<I>(t)), ...);
    std::cout << '\n';
}

template<class... Args>
void print_tuple(const std::tuple<Args...>& t) {
    print_tuple_impl(t, std::index_sequence_for<Args...>{});
}

int main() {
    print_tuple(std::make_tuple(1, "two", 3.0));
}
```

**Expected Output**
```
1 two 3
```

**Why this output?**  
`index_sequence_for` generates `0, 1, 2`; the fold expression expands `std::get<I>(t)` for each index, printing the tuple elements.

### Real-World Cases

- **Tuple utilities** – iterating over tuple elements.
- **Generic function application** – `std::apply` implementations.
- **Variadic template algorithms** – transforming parameter packs with indices.

## 10. `std::exchange`

### Definitions

**Core Definition**
`std::exchange` replaces the value of an object with a new value and returns the old value.

**Technical Definition**
Defined in `<utility>` since C++14, `std::exchange(obj, new_value)` assigns `new_value` to `obj` and returns the previous value of `obj`. It requires `T` to be `MoveConstructible` and `U` to be move-assignable to `T`. It became `constexpr` in C++20 and conditionally `noexcept` in C++23.

**Beginner-Friendly Explanation**
`std::exchange` is a “swap with a temporary”: it gives you the old value and puts a new one in its place. It is very useful in move constructors and move assignment operators.

### Purposes

- To implement move constructors and move assignment cleanly.
- To replace a value and retrieve the old one atomically.
- To simplify resource transfer.
- To avoid temporary variables in swap-like operations.

### Syntax Rules and Structure

**General Syntax**
```cpp
T old = std::exchange(obj, new_value);
```

**Component Breakdown**

| Component | Description |
|-----------|-------------|
| `obj` | Object whose value is replaced. |
| `new_value` | Value to assign to `obj`. |
| Return | The old value of `obj`. |

**Syntax Rules**
- `T` must be `MoveConstructible`.
- `U` must be move-assignable to `T`.
- The operation is not `noexcept` until C++23 (conditionally).

**Constraints and Limitations**
- Throws if the move operations throw.
- Not `noexcept` in C++14/17; cannot be used for `noexcept` move constructors without risk.

### Annotated Code Example

```cpp
#include <iostream>
#include <utility>

class Buffer {
    int* data_;
public:
    Buffer(int v) : data_(new int(v)) {}
    ~Buffer() { delete data_; }

    Buffer(Buffer&& other) noexcept
        : data_(std::exchange(other.data_, nullptr)) {}

    int value() const { return data_ ? *data_ : -1; }
};

int main() {
    Buffer a(42);
    Buffer b = std::move(a);
    std::cout << b.value() << ' ' << a.value() << '\n';
}
```

**Expected Output**
```
42 -1
```

**Why this output?**  
`std::exchange` transfers the pointer from `a` to `b` and sets `a`’s pointer to `nullptr`, so `a` is left in a valid empty state.

### Real-World Cases

- **Move constructors** – transferring resources safely.
- **Move assignment** – cleaning up the old resource and taking the new one.
- **State reset** – “give me the old value and reset to a new one.”

## 11. `std::quoted`

### Definitions

**Core Definition**
`std::quoted` is an I/O manipulator that inserts and extracts quoted strings, such as those found in CSV or XML.

**Technical Definition**
Defined in `<iomanip>` since C++14, `std::quoted(s, delim, escape)` returns an unspecified type that, when used with `operator<<`, surrounds `s` with `delim` and escapes any embedded `delim` or `escape` characters. When used with `operator>>`, it extracts a quoted string, unescaping embedded characters. Default `delim` is `"` and default `escape` is `\`.

**Beginner-Friendly Explanation**
`std::quoted` automatically adds quotes around a string when printing and removes them when reading, handling embedded quotes and escape characters correctly.

### Purposes

- To read and write CSV- or XML-style quoted strings.
- To ensure strings with spaces or delimiters round-trip correctly.
- To simplify parsing of delimited text.
- To provide a standard, portable way to quote strings in I/O.

### Syntax Rules and Structure

**General Syntax**
```cpp
std::cout << std::quoted(s);                 // insert with quotes
std::cin >> std::quoted(s);                  // extract quoted string
std::cout << std::quoted(s, delim, escape);  // custom delimiters
```

**Component Breakdown**

| Parameter | Default | Meaning |
|-----------|---------|---------|
| `s` | — | String to quote or unquote. |
| `delim` | `"` | Quote delimiter. |
| `escape` | `\` | Escape character. |

**Syntax Rules**
- Works with `std::string`, `const char*`, and (since C++17) `std::string_view`.
- Insertion escapes `delim` and `escape` by prefixing them with `escape`.
- Extraction reads until an unescaped `delim` is found.

**Constraints and Limitations**
- Requires C++14 or later.
- The return type is unspecified; do not rely on it.

### Annotated Code Example

```cpp
#include <iostream>
#include <iomanip>
#include <sstream>
#include <string>

int main() {
    std::string s = "hello \"world\"";
    std::stringstream ss;

    ss << std::quoted(s);
    std::cout << ss.str() << '\n';         // "hello \"world\""

    std::string out;
    ss >> std::quoted(out);
    std::cout << out << '\n';              // hello "world"
}
```

**Expected Output**
```
"hello \"world\""
hello "world"
```

**Why this output?**  
`std::quoted` inserts the string with surrounding quotes and escapes the embedded quotes; extraction reverses the process.

### Real-World Cases

- **CSV parsing** – reading/writing quoted fields.
- **Configuration files** – strings with spaces and quotes.
- **Log formatting** – unambiguous quoted values.
