# C++11 Features — Comprehensive Programming Cheat Sheet

## Topic Overview

### Definitions

**Core Definition**
C++11 (ISO/IEC 14882:2011) is the second major version of the C++ standard, introducing a large set of language and library features that modernised the language—most notably automatic type deduction, move semantics, lambdas, smart pointers, threading, and uniform initialization.

**Technical Definition**
C++11 is the ISO standard approved on 12 August 2011 (previously known as C++0x). It is the most important update since C++98, merging features from TR1 and Boost (thread library, `exception_ptr`, `error_code`, `error_condition`, iterator improvements) and adding core language features such as `auto`, `decltype`, rvalue references, move constructors, scoped enums, `constexpr`, list initialization, `nullptr`, variadic templates, and lambdas.

**Beginner-Friendly Explanation**
C++11 is the “modern C++” starting point. Before it, C++ felt old-fashioned: you had to write types everywhere, manually manage memory, and couldn't easily write a simple loop over a container. C++11 added features that make C++ feel like a modern language—type inference, safe smart pointers, built-in threading, and cleaner syntax.

### Key Characteristics

- **Automatic type deduction** – `auto` and `decltype` reduce verbosity.
- **Move semantics** – rvalue references enable efficient transfer of resources.
- **Lambda expressions** – inline anonymous functions.
- **Smart pointers** – `unique_ptr` and `shared_ptr` replace raw owning pointers.
- **Concurrency** – `std::thread`, `std::mutex`, and `std::chrono` bring threading into the standard library.
- **Uniform initialization** – brace initialization for all types.
- **Compile-time computation** – `constexpr` and `static_assert`.
- **Variadic templates** – templates that accept any number of arguments.

### Prerequisites

- Basic C++ syntax (variables, functions, classes, templates).
- Familiarity with pointers and references.
- Understanding of the standard library (containers, iterators, algorithms).
- Awareness of memory management (`new`/`delete`).

### Related Programming Areas

- **Move semantics** – foundational for modern C++ resource management.
- **Smart pointers** – RAII-based memory management.
- **Concurrency** – multithreaded programming with standard library primitives.
- **Generic programming** – variadic templates and `decltype`.
- **Compile-time programming** – `constexpr` and `static_assert`.

## 1. `auto`

### Definitions

**Core Definition**
`auto` is a type placeholder that tells the compiler to deduce a variable’s type from its initializer.

**Technical Definition**
`auto` (since C++11) allows the compiler to deduce the type of a variable from its initialiser using the rules of template argument deduction. The variable must always be initialised. `auto` is a type placeholder, not a type itself, so it cannot be used in casts or with `sizeof` or `typeid`.

**Beginner-Friendly Explanation**
`auto` means “let the compiler figure out the type.” Instead of writing `int x = 42;` you can write `auto x = 42;` and the compiler knows `x` is an `int`.

### Purposes

- To reduce verbosity when the type is obvious from the initialiser.
- To make code resilient to type changes (e.g., changing a container’s element type).
- To name types that are difficult or impossible to write (e.g., lambda closure types).
- To improve readability in generic code.

### Syntax Rules and Structure

**General Syntax**
```cpp
auto variable = expression;            // deduced from initializer
auto& ref = expression;                // reference deduction
auto* ptr = expression;                // pointer deduction
```

**Component Breakdown**

| Form | Deduction Rule |
|------|----------------|
| `auto x = expr;` | Drops references and top-level `const`. |
| `auto& x = expr;` | Deduces reference type. |
| `const auto& x = expr;` | Deduces `const` reference. |
| `auto* x = expr;` | Deduces pointer type. |

**Syntax Rules**
- The variable must have an initialiser.
- `auto` drops top-level `const` and references unless explicitly requested with `&` or `const`.
- `auto` can be used for function return types (C++14 trailing return type; C++14 return type deduction).

**Constraints and Limitations**
- Cannot be used for function parameters (until C++20 concepts/abbreviated function templates).
- Cannot be used without an initialiser.
- Deduction rules can be surprising with references and `const`.

### Annotated Code Example

```cpp
#include <iostream>
#include <vector>

int main() {
    auto x = 42;                        // int
    auto pi = 3.14159;                  // double
    auto& r = x;                        // int&
    const auto& cr = x;                 // const int&

    std::vector<int> v = {1, 2, 3};
    for (auto it = v.begin(); it != v.end(); ++it)
        std::cout << *it << ' ';
    std::cout << '\n' << x << ' ' << pi << '\n';
}
```

**Expected Output**
```
1 2 3
42 3.14159
```

**Why this output?**  
`auto` deduces `int` for `x`, `double` for `pi`, and the iterator type for `it`; the loop prints the vector elements.

### Real-World Cases

- **Iterators** – `auto it = map.begin();` avoids long type names.
- **Lambdas** – `auto f = [](int x){ return x * 2; };` – the closure type has no name.
- **Generic code** – reducing dependence on exact types.

## 2. Range-Based For

### Definitions

**Core Definition**
The range-based `for` loop iterates over every element of a range (container, array, or initializer list) without requiring explicit iterators.

**Technical Definition**
The range-based `for` (since C++11) executes a loop over a range, where the range is anything that provides `begin()` and `end()` (or is a C array). The syntax is `for (range_declaration : range_expression) loop_statement`. The `range_declaration` creates an iterating variable; `range_expression` is the container or range to iterate over.

**Beginner-Friendly Explanation**
Range-based `for` is a simpler way to loop over a collection: “for each item in the container, do something.” You don’t need to manage iterators or indices manually.

### Purposes

- To simplify iteration over containers.
- To avoid out-of-bounds errors from manual index loops.
- To improve readability and reduce boilerplate.
- To work uniformly with all standard containers, arrays, and initializer lists.

### Syntax Rules and Structure

**General Syntax**
```cpp
for (declaration : range) {
    // loop body
}
```

**Component Breakdown**

| Component | Description |
|-----------|-------------|
| `declaration` | Iterating variable; use `auto&` to modify, `const auto&` to read. |
| `range` | Container, array, or initializer list. |

**Syntax Rules**
- The range must provide `begin()` and `end()` (or be a C array).
- Use `auto&` to modify elements; `const auto&` to avoid copies.
- The loop variable is a copy unless a reference is used.

**Constraints and Limitations**
- Cannot easily skip elements or iterate in reverse.
- The range expression is evaluated once.

### Annotated Code Example

```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<int> numbers = {1, 2, 3, 4, 5};
    for (const auto& num : numbers)
        std::cout << num << ' ';
    std::cout << '\n';
}
```

**Expected Output**
```
1 2 3 4 5
```

**Why this output?**  
The range-based `for` visits each element of `numbers` in order.

### Real-World Cases

- **Container traversal** – printing, summing, transforming.
- **Array processing** – iterating C arrays.
- **Initializer lists** – `for (int x : {1, 2, 3})`.

## 3. Lambda Expressions

### Definitions

**Core Definition**
A lambda expression is an anonymous function object that can be defined inline and capture variables from its surrounding scope.

**Technical Definition**
A lambda expression (since C++11) creates a closure—an unnamed function object. The syntax is `[capture](parameters) -> return_type { body }`. The capture clause specifies which variables from the surrounding scope are accessible. The return type can be omitted for auto deduction unless there are multiple return statements with different types.

**Beginner-Friendly Explanation**
A lambda is a small function you can write right where you need it, without giving it a name. It can also “capture” variables from the surrounding code, so it can use them inside its body.

### Purposes

- To pass small functions to algorithms (`std::sort`, `std::find_if`).
- To create callbacks without defining a separate function object.
- To capture local state for deferred execution.
- To write concise, readable code for short operations.

### Syntax Rules and Structure

**General Syntax**
```cpp
[capture](parameters) -> return_type { body }
```

**Component Breakdown**

| Component | Description |
|-----------|-------------|
| `[capture]` | Which outer variables are captured (`[=]`, `[&]`, `[x]`, `[&x]`). |
| `(parameters)` | Parameter list (optional if no parameters). |
| `-> return_type` | Optional trailing return type. |
| `{ body }` | Lambda body. |

**Syntax Rules**
- `[=]` captures by value; `[&]` captures by reference.
- `mutable` allows modification of captured-by-value variables.
- Return type deduction is automatic unless specified.
- Lambdas are function objects; they can be stored in `std::function`.

**Constraints and Limitations**
- Capturing by reference can dangle if the lambda outlives the captured variable.
- `[=]` captures `this` by value (pointer) in member functions.

### Annotated Code Example

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

int main() {
    std::vector<int> v = {3, 1, 4, 1, 5};

    std::sort(v.begin(), v.end(), [](int a, int b) {
        return a > b;                   // descending order
    });

    int threshold = 2;
    auto count = std::count_if(v.begin(), v.end(),
        [threshold](int x) { return x > threshold; });

    for (int x : v) std::cout << x << ' ';
    std::cout << "\nCount > " << threshold << ": " << count << '\n';
}
```

**Expected Output**
```
5 4 3 1 1
Count > 2: 3
```

**Why this output?**  
The first lambda provides a custom comparator for `std::sort`; the second lambda captures `threshold` by value and counts elements greater than it.

### Real-World Cases

- **Custom comparators** – sorting by a specific field.
- **Predicates** – `std::find_if`, `std::remove_if`.
- **Callbacks** – event handlers, asynchronous continuations.
- **Thread functions** – `std::thread([]{ ... })`.

## 4. Rvalue References

### Definitions

**Core Definition**
An rvalue reference (`T&&`) is a reference that binds only to rvalues (temporary objects or objects explicitly marked as movable), enabling the implementation of move semantics and perfect forwarding.

**Technical Definition**
An rvalue reference to type `T` is created with the syntax `T&&`. Rvalue references only bind to rvalues. They support the implementation of move semantics (transferring resources from temporary objects) and perfect forwarding (preserving value categories through template functions). The compiler does not provide a default move constructor; you must define it.

**Beginner-Friendly Explanation**
An rvalue reference is a special kind of reference that can “claim” a temporary object. Because the temporary is about to be destroyed anyway, you can safely steal its resources instead of copying them.

### Purposes

- To enable move semantics (efficient resource transfer).
- To support perfect forwarding in templates.
- To distinguish lvalues from rvalues in overload resolution.
- To implement move constructors and move assignment operators.

### Syntax Rules and Structure

**General Syntax**
```cpp
T&& rref = temporary;                  // binds to rvalue
void f(T&& x);                         // rvalue reference parameter
```

**Component Breakdown**

| Form | Binds To |
|------|----------|
| `T&` | Lvalues only. |
| `const T&` | Lvalues and rvalues (read-only). |
| `T&&` | Rvalues only. |
| `T&&` (template) | Forwarding reference (binds to anything). |

**Syntax Rules**
- `T&&` binds only to rvalues; `T&&` in a template context is a forwarding reference.
- Use `std::move` to cast an lvalue to an rvalue.
- Move constructors take `T&&` parameters.

**Constraints and Limitations**
- An rvalue reference is itself an lvalue; use `std::move` to pass it along as an rvalue.
- Overloading on `T&&` and `const T&` requires careful design.

### Annotated Code Example

```cpp
#include <iostream>
#include <utility>

void process(int& x)  { std::cout << "lvalue: " << x << '\n'; }
void process(int&& x) { std::cout << "rvalue: " << x << '\n'; }

int main() {
    int a = 10;
    process(a);                        // lvalue
    process(20);                       // rvalue
    process(std::move(a));             // rvalue (cast)
}
```

**Expected Output**
```
lvalue: 10
rvalue: 20
rvalue: 10
```

**Why this output?**  
`a` is an lvalue; `20` is a temporary rvalue; `std::move(a)` casts `a` to an rvalue, selecting the rvalue overload.

### Real-World Cases

- **Move constructors** – `MyType(MyType&& other) noexcept;`.
- **Perfect forwarding** – `template<class T> void wrapper(T&& arg) { f(std::forward<T>(arg)); }`.
- **Optimised string/vector operations** – avoiding deep copies.

## 5. Move Semantics

### Definitions

**Core Definition**
Move semantics is the transfer of ownership of a resource from one object to another, typically from a temporary (rvalue) to a new object, leaving the source in a valid but unspecified state.

**Technical Definition**
Move semantics (since C++11) enables the transfer of resources (such as dynamically allocated memory) from one object to another. It works because resources can be transferred from temporary objects that cannot be referenced elsewhere. To implement move semantics, you provide a move constructor and optionally a move assignment operator. Moving a `std::vector` is just copying some pointers and internal state—copying would involve copying every contained element.

**Beginner-Friendly Explanation**
Moving means “stealing” resources instead of copying them. If you have a big vector and you’re about to throw it away, you can give its internal array to a new vector instead of copying every element. This is much faster.

### Purposes

- To improve performance by avoiding deep copies.
- To enable transfer of non-copyable resources (e.g., `unique_ptr`).
- To make containers reallocate efficiently.
- To support return-by-value of large objects.

### Syntax Rules and Structure

**General Syntax**
```cpp
class MyType {
public:
    MyType(MyType&& other) noexcept;             // move constructor
    MyType& operator=(MyType&& other) noexcept;  // move assignment
};
```

**Component Breakdown**

| Member | Signature | Role |
|--------|-----------|------|
| Move constructor | `T(T&&) noexcept` | Transfers resources from an rvalue. |
| Move assignment | `T& operator=(T&&) noexcept` | Transfers resources from an rvalue. |
| `std::move` | `std::move(x)` | Casts an lvalue to an rvalue. |

**Syntax Rules**
- Move constructors and move assignment should be `noexcept`.
- The moved-from object must be left in a valid state (destructible, assignable).
- `std::move` does not move anything; it is a cast.

**Constraints and Limitations**
- If a type has no move constructor, the compiler falls back to copying.
- Move semantics only applies to rvalues; lvalues must be explicitly cast with `std::move`.

### Annotated Code Example

```cpp
#include <iostream>
#include <utility>
#include <vector>

class Buffer {
    int* data_;
public:
    explicit Buffer(int v) : data_(new int(v)) {}
    ~Buffer() { delete data_; }

    Buffer(const Buffer& other) : data_(new int(*other.data_)) {
        std::cout << "Copy\n";
    }

    Buffer(Buffer&& other) noexcept
        : data_(std::exchange(other.data_, nullptr)) {
        std::cout << "Move\n";
    }

    int value() const { return data_ ? *data_ : -1; }
};

int main() {
    Buffer a(10);
    Buffer b = a;                      // copy
    Buffer c = std::move(a);           // move
    std::cout << b.value() << ' ' << c.value() << '\n';
}
```

**Expected Output**
```
Copy
Move
10 10
```

**Why this output?**  
`Buffer b = a` copies `a`; `Buffer c = std::move(a)` moves from `a` (leaving `a` empty). `b` and `c` both hold `10`.

### Real-World Cases

- **Standard containers** – `std::vector` reallocation uses moves.
- **Return by value** – returning large objects efficiently.
- **`unique_ptr`** – move-only ownership transfer.
- **String and buffer classes** – avoiding deep copies.

## 6. `nullptr`

### Definitions

**Core Definition**
`nullptr` is a null pointer literal of type `std::nullptr_t` that replaces the problematic `NULL` macro and integer literal `0`.

**Technical Definition**
`nullptr` (since C++11) is a keyword representing a null pointer constant. It has the distinct type `std::nullptr_t`, which is deliberately not an integer type. This allows overload resolution to distinguish between pointer and integer arguments, solving the ambiguity caused by `NULL` (which is often defined as `0`).

**Beginner-Friendly Explanation**
`nullptr` is the modern way to say “no pointer.” Unlike `NULL` or `0`, it cannot be confused with an integer, so overloaded functions can tell the difference between a pointer argument and an integer argument.

### Purposes

- To provide a type-safe null pointer constant.
- To resolve overload ambiguity between pointer and integer types.
- To improve code clarity and safety.
- To replace `NULL` and `0` in pointer contexts.

### Syntax Rules and Structure

**General Syntax**
```cpp
int* p = nullptr;
if (p == nullptr) { ... }
```

**Component Breakdown**

| Literal | Type |
|---------|------|
| `nullptr` | `std::nullptr_t` |
| `NULL` | Implementation-defined (often `0`) |
| `0` | `int` |

**Syntax Rules**
- `nullptr` is implicitly convertible to any pointer type.
- It cannot be converted to an integer type.
- `std::nullptr_t` is the type of `nullptr`.

**Constraints and Limitations**
- `nullptr` requires C++11 or later.
- Some older APIs may still expect `NULL`.

### Annotated Code Example

```cpp
#include <iostream>

void f(int x)    { std::cout << "int: " << x << '\n'; }
void f(char* p)  { std::cout << "pointer: " << (p ? p : "null") << '\n'; }

int main() {
    f(0);                              // int
    f(nullptr);                        // pointer (no ambiguity)
}
```

**Expected Output**
```
int: 0
pointer: null
```

**Why this output?**  
`0` matches the `int` overload; `nullptr` matches the pointer overload without ambiguity.

### Real-World Cases

- **Pointer initialisation** – `int* p = nullptr;`.
- **Overload resolution** – avoiding `NULL` ambiguity.
- **Generic code** – type-safe null checking.

## 7. `enum class`

### Definitions

**Core Definition**
`enum class` (scoped enumeration) is a strongly typed enumeration whose enumerators are scoped within the enumeration and do not implicitly convert to integers.

**Technical Definition**
Scoped enumerations (since C++11) are declared with `enum class` (or `enum struct`). Unlike traditional enums, they do not implicitly convert to integers, their enumerators are scoped (`Color::red`), and the underlying type can be specified. They solve the problems of name pollution and unintended implicit conversions.

**Beginner-Friendly Explanation**
`enum class` is a “strong enum.” Its values are kept inside a namespace-like scope, and you cannot accidentally use them as integers. This makes code safer and clearer.

### Purposes

- To avoid enumerator name pollution.
- To prevent implicit conversion to integers.
- To allow forward declaration.
- To specify the underlying type explicitly.

### Syntax Rules and Structure

**General Syntax**
```cpp
enum class Color { red, green, blue };
Color c = Color::red;
```

**Component Breakdown**

| Feature | Unscoped `enum` | Scoped `enum class` |
|---------|-----------------|---------------------|
| Scope | Enumerators in enclosing scope | Enumerators scoped |
| Implicit conversion to int | Yes | No |
| Forward declaration | No (before C++11) | Yes |
| Underlying type | Implementation-defined | Can be specified |

**Syntax Rules**
- Enumerators are accessed with `EnumName::enumerator`.
- Explicit cast is required to convert to integer: `static_cast<int>(Color::red)`.
- Underlying type can be specified: `enum class Color : unsigned char { red, green };`.

**Constraints and Limitations**
- Requires explicit casts for arithmetic.
- Not implicitly convertible to `int`.

### Annotated Code Example

```cpp
#include <iostream>

enum class Color { red, green, blue };

int main() {
    Color c = Color::green;
    // int x = c;                      // error: no implicit conversion
    int x = static_cast<int>(c);
    std::cout << x << '\n';            // 1
}
```

**Expected Output**
```
1
```

**Why this output?**  
`Color::green` is explicitly cast to `int`; the value is `1` (enumerators start at `0`).

### Real-World Cases

- **Type-safe state machines** – `State::running`, `State::stopped`.
- **Bit flags with explicit underlying type**.
- **API design** – avoiding name clashes.

## 8. `constexpr`

### Definitions

**Core Definition**
`constexpr` is a specifier that indicates that a variable or function can be evaluated at compile time.

**Technical Definition**
`constexpr` (since C++11, improved in C++14) declares that a variable’s value can be computed at compile time, or that a function can be evaluated at compile time when given constant arguments. A `constexpr` variable is implicitly `const` and its initialiser must be a constant expression. A `constexpr` function can be called at compile time (producing a constant expression) or at runtime.

**Beginner-Friendly Explanation**
`constexpr` means “this can be computed by the compiler.” For variables, it guarantees the value is known at compile time. For functions, it allows the function to be used in constant expressions (like array sizes or template arguments).

### Purposes

- To move computation from runtime to compile time.
- To allow variables to be used in constant expressions.
- To enforce compile-time evaluation where required.
- To improve performance and enable template metaprogramming.

### Syntax Rules and Structure

**General Syntax**
```cpp
constexpr int max_size = 100;
constexpr int square(int x) { return x * x; }
```

**Component Breakdown**

| Form | Meaning |
|------|---------|
| `constexpr` variable | Value known at compile time; implicitly `const`. |
| `constexpr` function | Can be evaluated at compile time for constant arguments. |

**Syntax Rules**
- A `constexpr` variable must be initialised with a constant expression.
- A `constexpr` function must have a body that is valid for constant evaluation (C++14 relaxations).
- `constexpr` functions are implicitly `inline`.

**Constraints and Limitations**
- C++11 `constexpr` functions were restricted to a single `return` statement; C++14 relaxed this.
- Not all types are literal types.

### Annotated Code Example

```cpp
#include <iostream>

constexpr int square(int x) { return x * x; }

int main() {
    constexpr int result = square(5);   // compile-time
    std::cout << result << '\n';
    std::cout << square(6) << '\n';     // runtime or compile-time
}
```

**Expected Output**
```
25
36
```

**Why this output?**  
`square(5)` is a constant expression, so `result` is computed at compile time. `square(6)` is used at runtime.

### Real-World Cases

- **Array sizes** – `constexpr std::size_t N = 10; int arr[N];`.
- **Template arguments** – `std::array<int, square(4)>`.
- **Compile-time validation** – `static_assert(square(3) == 9)`.

## 9. Variadic Templates

### Definitions

**Core Definition**
A variadic template is a template that accepts a variable number of template arguments (zero or more) through a parameter pack.

**Technical Definition**
Variadic templates (since C++11) accept a variable number of template arguments via parameter packs. The syntax uses `typename... Args` for a template parameter pack, and `Args... args` for a function parameter pack. `sizeof...(Args)` returns the number of elements in the pack at compile time. Pack expansion repeats a pattern for each element in the pack.

**Beginner-Friendly Explanation**
A variadic template is a template that can take any number of arguments of any types. It is like a function that can accept 0, 1, 2, or 100 arguments—whatever you give it.

### Purposes

- To write functions and classes that accept any number of arguments.
- To implement type-safe `printf`-style functions.
- To build `std::tuple`, `std::make_shared`, and other generic utilities.
- To support perfect forwarding of argument packs.

### Syntax Rules and Structure

**General Syntax**
```cpp
template <typename... Args>
void func(Args... args) {
    // sizeof...(Args) gives the number of arguments
}
```

**Component Breakdown**

| Component | Description |
|-----------|-------------|
| `typename... Args` | Template parameter pack. |
| `Args... args` | Function parameter pack. |
| `args...` | Pack expansion. |
| `sizeof...(Args)` | Number of elements in the pack. |

**Syntax Rules**
- A pack can be expanded in function arguments, initializer lists, base classes, and template arguments.
- The position of `...` determines the expansion pattern.
- Recursive expansion is the classic technique before C++17 fold expressions.

**Constraints and Limitations**
- A template class can contain at most one template parameter pack.
- Pack expansion syntax can be tricky; `g(args...)` and `g(transform(args)...)` are different.

### Annotated Code Example

```cpp
#include <iostream>

void print() { std::cout << '\n'; }

template <typename T, typename... Rest>
void print(T first, Rest... rest) {
    std::cout << first << ' ';
    print(rest...);
}

int main() {
    print(1, 2.5, "three", '4');
}
```

**Expected Output**
```
1 2.5 three 4
```

**Why this output?**  
The recursive expansion prints `first`, then recurses with the remaining arguments; the base case ends the recursion.

### Real-World Cases

- **Type-safe logging/formatting** – replacing C-style `printf`.
- **`std::make_shared`** – forwarding constructor arguments.
- **`std::tuple`** – storing heterogeneous values.

## 10. `std::unique_ptr` and `std::shared_ptr`

### Definitions

**Core Definition**
`std::unique_ptr` is a smart pointer with exclusive ownership; `std::shared_ptr` is a smart pointer with shared ownership via reference counting.

**Technical Definition**
`std::unique_ptr<T>` (since C++11) manages a single object with exclusive ownership; it is move-only and destroys the object when it goes out of scope. `std::shared_ptr<T>` manages shared ownership; multiple `shared_ptr` instances own the same object, and the object is destroyed when the last owner is destroyed. Both are RAII wrappers that automatically release resources.

**Beginner-Friendly Explanation**
`unique_ptr` is the “only owner” pointer—nobody else can own the object. `shared_ptr` is the “shared owner” pointer—many parts of the program can own it, and it is deleted when the last owner lets go.

### Purposes

- To eliminate manual `new`/`delete` and prevent leaks.
- To express ownership semantics clearly.
- To provide exception-safe resource management.
- To enable shared ownership when needed.

### Syntax Rules and Structure

**General Syntax**
```cpp
std::unique_ptr<T> up = std::make_unique<T>(args...);    // C++14
std::shared_ptr<T> sp = std::make_shared<T>(args...);
```

**Component Breakdown**

| Smart Pointer | Ownership | Copyable |
|---------------|-----------|----------|
| `unique_ptr` | Exclusive | No (move only) |
| `shared_ptr` | Shared | Yes |
| `weak_ptr` | Non-owning observer | Yes |

**Syntax Rules**
- Use `std::make_unique` (C++14) and `std::make_shared` to create smart pointers.
- `unique_ptr` cannot be copied; use `std::move`.
- `shared_ptr` uses atomic reference counting (thread-safe count, not object).

**Constraints and Limitations**
- `shared_ptr` has overhead from reference counting.
- Cyclic references require `weak_ptr`.

### Annotated Code Example

```cpp
#include <iostream>
#include <memory>

int main() {
    auto up = std::make_unique<int>(42);
    std::cout << *up << '\n';          // 42

    auto sp1 = std::make_shared<int>(10);
    auto sp2 = sp1;                    // shared
    std::cout << sp1.use_count() << '\n'; // 2
}
```

**Expected Output**
```
42
2
```

**Why this output?**  
`unique_ptr` owns `42`; `shared_ptr` has two owners after the copy, so `use_count()` is 2.

### Real-World Cases

- **Factory functions** – returning `unique_ptr`.
- **Shared configuration** – `shared_ptr` for shared resources.
- **Pimpl idiom** – `unique_ptr<Impl>`.

## 11. `std::thread` and `std::mutex`

### Definitions

**Core Definition**
`std::thread` represents a single thread of execution; `std::mutex` is a mutual exclusion primitive used to protect shared data from concurrent access.

**Technical Definition**
`std::thread` (since C++11) starts a new thread of execution. `std::mutex` provides exclusive ownership of a lock; `std::lock_guard` and `std::unique_lock` are RAII wrappers for mutexes. These are part of the C++11 thread support library, merged from Boost.

**Beginner-Friendly Explanation**
`std::thread` lets you run code in parallel. `std::mutex` is like a lock on a door—only one thread can hold it at a time, preventing data races.

### Purposes

- To run code concurrently on multiple cores.
- To protect shared data from race conditions.
- To synchronise access to resources.
- To implement parallel algorithms and pipelines.

### Syntax Rules and Structure

**General Syntax**
```cpp
std::thread t(function, args...);
t.join();                              // wait for thread

std::mutex m;
{
    std::lock_guard<std::mutex> lock(m);
    // critical section
}
```

**Component Breakdown**

| Component | Role |
|-----------|------|
| `std::thread` | Thread object. |
| `std::mutex` | Mutual exclusion lock. |
| `std::lock_guard` | RAII lock (locks on construction, unlocks on destruction). |

**Syntax Rules**
- Every `std::thread` must be either `join()`ed or `detach()`ed before destruction.
- `lock_guard` cannot be copied or moved.
- `std::mutex` is non-copyable.

**Constraints and Limitations**
- Thread creation has overhead.
- Data races are undefined behaviour.
- Deadlocks can occur with multiple mutexes.

### Annotated Code Example

```cpp
#include <iostream>
#include <thread>
#include <mutex>

std::mutex mtx;
int counter = 0;

void increment(int n) {
    for (int i = 0; i < n; ++i) {
        std::lock_guard<std::mutex> lock(mtx);
        ++counter;
    }
}

int main() {
    std::thread t1(increment, 1000);
    std::thread t2(increment, 1000);
    t1.join();
    t2.join();
    std::cout << counter << '\n';
}
```

**Expected Output**
```
2000
```

**Why this output?**  
The mutex ensures that only one thread increments `counter` at a time, preventing a data race.

### Real-World Cases

- **Parallel computation** – dividing work across threads.
- **Producer-consumer queues** – synchronised queues.
- **Background tasks** – logging, I/O.

## 12. `std::chrono`

### Definitions

**Core Definition**
`std::chrono` is the standard library’s time library, providing type-safe durations, time points, and clocks.

**Technical Definition**
The `<chrono>` header (since C++11) provides `duration` (a time interval), `time_point` (an instant), and `clock` (a time source). Standard clocks include `system_clock`, `steady_clock`, and `high_resolution_clock`. It replaces the older C `<ctime>` API with type-safe, compile-time-ratio-based abstractions.

**Beginner-Friendly Explanation**
`std::chrono` lets you work with time safely: `5s`, `100ms`, and `2h` are distinct types, so you cannot accidentally add seconds to milliseconds. It also provides clocks for measuring elapsed time and getting the current time.

### Purposes

- To represent time intervals and instants with type safety.
- To measure elapsed time reliably.
- To schedule timeouts and delays.
- To convert between time units explicitly.

### Syntax Rules and Structure

**General Syntax**
```cpp
#include <chrono>
using namespace std::chrono;

auto start = steady_clock::now();
auto elapsed = duration_cast<milliseconds>(steady_clock::now() - start);
```

**Component Breakdown**

| Component | Description |
|-----------|-------------|
| `duration` | Time interval (e.g., `seconds`, `milliseconds`). |
| `time_point` | Instant in time. |
| `steady_clock` | Monotonic clock (for intervals). |
| `system_clock` | Wall-clock time. |

**Syntax Rules**
- Durations support arithmetic; conversions require `duration_cast`.
- `steady_clock` is monotonic and should be used for measuring intervals.
- `system_clock` is for wall-clock time.

**Constraints and Limitations**
- `high_resolution_clock` is often an alias; prefer explicit clocks.

### Annotated Code Example

```cpp
#include <iostream>
#include <chrono>
#include <thread>

int main() {
    using namespace std::chrono;
    auto start = steady_clock::now();
    std::this_thread::sleep_for(100ms);
    auto elapsed = duration_cast<milliseconds>(steady_clock::now() - start);
    std::cout << elapsed.count() << " ms\n";
}
```

**Expected Output** (approximately)
```
100 ms
```

**Why this output?**  
`steady_clock` measures the sleep interval; `duration_cast` converts to milliseconds.

### Real-World Cases

- **Profiling** – measuring execution time.
- **Timeouts** – `sleep_for`, deadlines.
- **Scheduling** – time points for events.

## 13. Uniform Initialization and Initializer Lists

### Definitions

**Core Definition**
Uniform initialization is a syntax using braces `{}` to initialise any object, regardless of type; `std::initializer_list` is a lightweight array-like type used to pass a list of values to constructors and functions.

**Technical Definition**
Uniform initialization (since C++11) allows any object of primitive, aggregate, or class type to be initialised using brace syntax. `std::initializer_list<T>` is a standard library type that allows constructors and functions to accept a variable-length list of values. It is the mechanism behind `std::vector<int> v = {1, 2, 3};`.

**Beginner-Friendly Explanation**
Uniform initialization means you can use the same brace syntax everywhere: `int x{5};`, `std::vector<int> v{1, 2, 3};`, `Point p{1, 2};`. An initializer list is what makes `{1, 2, 3}` work as a function argument.

### Purposes

- To provide a single, consistent initialisation syntax.
- To prevent narrowing conversions.
- To initialise containers and aggregates cleanly.
- To allow functions to accept variable-length argument lists.

### Syntax Rules and Structure

**General Syntax**
```cpp
int x{5};
std::vector<int> v = {1, 2, 3};
void f(std::initializer_list<int> list);
f({1, 2, 3});
```

**Component Breakdown**

| Form | Meaning |
|------|---------|
| `T x{value};` | Direct-list-initialization. |
| `T x = {value};` | Copy-list-initialization. |
| `std::initializer_list<T>` | Lightweight list passed to functions/constructors. |

**Syntax Rules**
- Brace initialization disallows narrowing conversions (e.g., `int x{3.14}` is an error).
- `std::initializer_list` is automatically constructed from a braced list.
- Constructors taking `initializer_list` are preferred during overload resolution.

**Constraints and Limitations**
- `std::initializer_list` elements are `const` and stored in read-only memory.
- The underlying array’s lifetime ends when the `initializer_list` object is destroyed.

### Annotated Code Example

```cpp
#include <iostream>
#include <vector>
#include <initializer_list>

void print(std::initializer_list<int> list) {
    for (int x : list) std::cout << x << ' ';
    std::cout << '\n';
}

int main() {
    int a{10};
    std::vector<int> v{1, 2, 3};
    print({4, 5, 6});
    std::cout << a << '\n';
}
```

**Expected Output**
```
4 5 6
10
```

**Why this output?**  
`a` is direct-list-initialised; `v` uses initializer-list construction; `print` receives a temporary `initializer_list`.

### Real-World Cases

- **Container initialisation** – `std::vector<std::string> names{"Alice", "Bob"};`.
- **Aggregate initialisation** – `Point p{1, 2};`.
- **Function arguments** – `f({1, 2, 3});`.

## 14. `std::array` and `std::tuple`

### Definitions

**Core Definition**
`std::array` is a fixed-size array container; `std::tuple` is a fixed-size heterogeneous collection.

**Technical Definition**
`std::array<T, N>` (since C++11) is a container that encapsulates a fixed-size array, combining C-array performance with container interface (iterators, `size()`, `at()`). `std::tuple<Types...>` (since C++11) is a fixed-size collection of heterogeneous values, accessed via `std::get<I>` or `std::get<T>`.

**Beginner-Friendly Explanation**
`std::array` is a safer, more convenient C array. `std::tuple` is like a `std::pair` but for any number of values of different types.

### Purposes

- To provide fixed-size, stack-allocated containers.
- To group heterogeneous values.
- To return multiple values from a function.
- To support structured bindings (C++17) and metaprogramming.

### Syntax Rules and Structure

**General Syntax**
```cpp
std::array<int, 3> a = {1, 2, 3};
std::tuple<int, double, std::string> t = {1, 2.5, "three"};
std::get<0>(t);
```

**Component Breakdown**

| Container | Characteristics |
|-----------|-----------------|
| `std::array` | Fixed size, contiguous, stack-allocated. |
| `std::tuple` | Fixed size, heterogeneous, `std::get` access. |

**Syntax Rules**
- `std::array` size is a compile-time constant.
- `std::tuple` elements are accessed by index or type (if unique).
- Both support comparison and structured bindings (C++17).

**Constraints and Limitations**
- `std::array` size cannot change.
- `std::tuple` elements are not named.

### Annotated Code Example

```cpp
#include <iostream>
#include <array>
#include <tuple>
#include <string>

int main() {
    std::array<int, 3> a = {1, 2, 3};
    std::cout << a[1] << '\n';          // 2

    std::tuple<int, std::string, double> t = {1, "two", 3.0};
    std::cout << std::get<1>(t) << '\n'; // two
}
```

**Expected Output**
```
2
two
```

**Why this output?**  
`std::array` provides array-like access; `std::tuple` uses `std::get<I>` for element access.

### Real-World Cases

- **Fixed-size buffers** – `std::array<char, 256>`.
- **Multi-value returns** – `std::tuple<bool, int, std::string>`.
- **Mathematical vectors** – small fixed-size arrays.

## 15. `std::function` and `std::bind`

### Definitions

**Core Definition**
`std::function` is a polymorphic function wrapper that can store any callable; `std::bind` creates a callable by binding arguments to a function.

**Technical Definition**
`std::function<R(Args...)>` (since C++11) is a general-purpose polymorphic function wrapper that can store, copy, and invoke any `CopyConstructible` callable. `std::bind` (since C++11) generates a forwarding call wrapper that binds some arguments to a callable, using placeholders (`std::placeholders::_1`, etc.) for unbound parameters.

**Beginner-Friendly Explanation**
`std::function` is a “universal function holder”—you can put any function, lambda, or functor into it. `std::bind` is a way to create a new function by fixing some arguments of an existing function.

### Purposes

- To store callables in variables, containers, or class members.
- To pass callbacks with a uniform type.
- To create partially applied functions.
- To adapt functions with different signatures.

### Syntax Rules and Structure

**General Syntax**
```cpp
std::function<int(int, int)> f = [](int a, int b) { return a + b; };
auto g = std::bind(function, arg1, std::placeholders::_1);
```

**Component Breakdown**

| Component | Role |
|-----------|------|
| `std::function` | Type-erased callable wrapper. |
| `std::bind` | Partial application and argument reordering. |
| `std::placeholders::_1` | Placeholder for the first unbound argument. |

**Syntax Rules**
- `std::function` requires the callable to be copy-constructible.
- `std::bind` returns an unspecified callable object.
- Use `std::ref` to bind references.

**Constraints and Limitations**
- `std::function` has overhead from type erasure.
- `std::bind` can be hard to read; lambdas are often clearer.

### Annotated Code Example

```cpp
#include <iostream>
#include <functional>

int add(int a, int b) { return a + b; }

int main() {
    std::function<int(int, int)> f = add;
    std::cout << f(2, 3) << '\n';       // 5

    auto add5 = std::bind(add, 5, std::placeholders::_1);
    std::cout << add5(10) << '\n';      // 15
}
```

**Expected Output**
```
5
15
```

**Why this output?**  
`f` stores `add` and calls it with `(2, 3)`. `add5` binds the first argument to `5`; calling `add5(10)` invokes `add(5, 10)`.

### Real-World Cases

- **Callbacks** – event handlers, GUI actions.
- **Strategy pattern** – selecting algorithms at runtime.
- **Partial application** – specialising functions.

## 16. `std::ref` and `std::cref`

### Definitions

**Core Definition**
`std::ref` and `std::cref` are helper functions that create `std::reference_wrapper` objects, allowing references to be stored and passed by value.

**Technical Definition**
`std::ref(T&)` returns a `std::reference_wrapper<T>`; `std::cref(const T&)` returns a `std::reference_wrapper<const T>`. These are used to pass references to functions like `std::bind` and `std::thread`, which otherwise copy their arguments. `std::reference_wrapper` is a copyable, assignable wrapper around a reference.

**Beginner-Friendly Explanation**
`std::ref` lets you pass something by reference to functions that normally copy. It is especially useful with `std::bind` and `std::thread`.

### Purposes

- To store references in containers.
- To pass references to `std::bind`, `std::thread`, and algorithms.
- To avoid copies in generic code.
- To provide const and non-const reference wrappers.

### Syntax Rules and Structure

**General Syntax**
```cpp
auto r = std::ref(obj);                // reference_wrapper<T>
auto cr = std::cref(obj);              // reference_wrapper<const T>
```

**Component Breakdown**

| Function | Returns |
|----------|---------|
| `std::ref(T&)` | `reference_wrapper<T>` |
| `std::cref(const T&)` | `reference_wrapper<const T>` |

**Syntax Rules**
- `std::ref` cannot bind to rvalues (deleted overload).
- The referenced object must outlive the wrapper.

**Constraints and Limitations**
- Dangling references if the original object is destroyed.

### Annotated Code Example

```cpp
#include <iostream>
#include <functional>

void increment(int& x) { ++x; }

int main() {
    int n = 0;
    auto bound = std::bind(increment, std::ref(n));
    bound();
    std::cout << n << '\n';            // 1
}
```

**Expected Output**
```
1
```

**Why this output?**  
`std::ref(n)` ensures `std::bind` stores a reference; `increment` modifies the original `n`.

### Real-World Cases

- **`std::bind`** – passing arguments by reference.
- **`std::thread`** – sharing data between threads.
- **Algorithms** – passing references to functions expecting values.

## 17. `decltype`

### Definitions

**Core Definition**
`decltype` is a specifier that yields the declared type of an expression without evaluating it.

**Technical Definition**
`decltype(expression)` (since C++11) returns the type of the expression as declared. If the expression is an lvalue, `decltype` yields a reference type; if it is an rvalue, it yields the value type. It is commonly used in trailing return types and generic programming to deduce types from expressions.

**Beginner-Friendly Explanation**
`decltype` asks the compiler: “What is the type of this expression?” It is useful when you need to name a type that is hard to write, or when the type depends on a template parameter.

### Purposes

- To deduce types in generic code.
- To write trailing return types.
- To preserve references and `const` in deduced types.
- To avoid writing complex type names.

### Syntax Rules and Structure

**General Syntax**
```cpp
decltype(expression) variable;
auto f() -> decltype(expression);
```

**Component Breakdown**

| Expression Category | `decltype` Result |
|---------------------|-------------------|
| Lvalue | `T&` |
| Rvalue | `T` |
| `decltype(auto)` (C++14) | Deduces references |

**Syntax Rules**
- `decltype` does not evaluate the expression.
- Parentheses matter: `decltype((x))` yields `T&`; `decltype(x)` yields `T`.

**Constraints and Limitations**
- `decltype` is a compile-time construct; it has no runtime effect.

### Annotated Code Example

```cpp
#include <iostream>
#include <vector>

int main() {
    int x = 10;
    decltype(x) y = 20;                // int
    decltype((x)) z = x;               // int&

    std::vector<int> v = {1, 2, 3};
    decltype(v.begin()) it = v.begin(); // iterator type
    std::cout << *it << '\n';
}
```

**Expected Output**
```
1
```

**Why this output?**  
`decltype(x)` is `int`; `decltype((x))` is `int&`; `decltype(v.begin())` is the vector’s iterator type.

### Real-World Cases

- **Trailing return types** – `auto f() -> decltype(a + b);`.
- **Generic wrappers** – deducing return types.
- **Metaprogramming** – type introspection.

## 18. `static_assert`

### Definitions

**Core Definition**
`static_assert` is a compile-time assertion that checks a constant expression and produces a compile error if it is false.

**Technical Definition**
`static_assert(condition, message)` (since C++11) evaluates a constant expression at compile time. If the condition is `false`, the compiler emits an error with the given message. It is commonly used to validate template parameters and type properties.

**Beginner-Friendly Explanation**
`static_assert` is a way to say “this must be true” and have the compiler check it. If it is not true, compilation fails with your message.

### Purposes

- To enforce compile-time constraints.
- To validate template parameters.
- To document assumptions that the compiler can verify.
- To catch errors early.

### Syntax Rules and Structure

**General Syntax**
```cpp
static_assert(condition, "message");
```

**Component Breakdown**

| Component | Description |
|-----------|-------------|
| `condition` | A constant expression convertible to `bool`. |
| `message` | A string literal shown on failure. |

**Syntax Rules**
- Available since C++11; C++17 allows omitting the message.
- The condition must be a constant expression.

**Constraints and Limitations**
- Only works on compile-time constants.

### Annotated Code Example

```cpp
#include <iostream>
#include <type_traits>

template <typename T>
void process(T value) {
    static_assert(std::is_integral_v<T>, "T must be an integral type");
    std::cout << value << '\n';
}

int main() {
    process(42);                       // OK
    // process(3.14);                  // compile error
}
```

**Expected Output**
```
42
```

**Why this output?**  
`static_assert` passes for `int`; for `double`, compilation would fail with the message.

### Real-World Cases

- **Template constraints** – requiring specific type traits.
- **Architecture checks** – `static_assert(sizeof(int) == 4)`.
- **Documenting assumptions** – compile-time verification.

## 19. `alignas` and `alignof`

### Definitions

**Core Definition**
`alignas` specifies the alignment requirement of a type or variable; `alignof` queries the alignment requirement of a type.

**Technical Definition**
`alignas` (since C++11) is a specifier that sets the alignment requirement of a variable or type. `alignof` (since C++11) is an operator that returns the alignment requirement of a type. These are used for low-level memory management, SIMD, and hardware interfacing.

**Beginner-Friendly Explanation**
`alignas` says “store this object at a memory address that is a multiple of N.” `alignof` asks “what is the alignment requirement of this type?”

### Purposes

- To control memory alignment for performance or hardware requirements.
- To query alignment requirements.
- To support SIMD and cache-line alignment.
- To interface with hardware registers.

### Syntax Rules and Structure

**General Syntax**
```cpp
alignas(N) T variable;                 // set alignment
auto a = alignof(T);                   // query alignment
```

**Component Breakdown**

| Specifier/Operator | Meaning |
|--------------------|---------|
| `alignas(N)` | Align to at least `N` bytes. |
| `alignas(T)` | Align as `T`. |
| `alignof(T)` | Returns alignment of `T`. |

**Syntax Rules**
- `alignas` cannot reduce alignment below the natural alignment.
- `alignof` returns a `std::size_t`.

**Constraints and Limitations**
- Over-alignment may increase memory usage.

### Annotated Code Example

```cpp
#include <iostream>
#include <cstddef>

struct alignas(16) Vec4 {
    float x, y, z, w;
};

int main() {
    std::cout << alignof(Vec4) << '\n';    // 16
    std::cout << sizeof(Vec4) << '\n';     // 16
}
```

**Expected Output**
```
16
16
```

**Why this output?**  
`alignas(16)` forces `Vec4` to be 16-byte aligned; `alignof` reports the alignment; `sizeof` shows the size.

### Real-World Cases

- **SIMD vectors** – 16-byte alignment for SSE.
- **Cache-line alignment** – avoiding false sharing.
- **Hardware registers** – specific alignment requirements.

## 20. Attributes

### Definitions

**Core Definition**
Attributes are standardised annotations (`[[...]]`) that provide additional information to the compiler, such as deprecation warnings or optimization hints.

**Technical Definition**
Attributes (since C++11) use the syntax `[[attribute]]` and can be applied to declarations, statements, and types. Standard attributes include `[[noreturn]]`, `[[deprecated]]`, `[[nodiscard]]`, `[[maybe_unused]]`, and `[[fallthrough]]`. They allow compilers to issue warnings or optimise code based on the annotation.

**Beginner-Friendly Explanation**
Attributes are notes to the compiler. For example, `[[deprecated]]` tells the compiler to warn anyone who uses the function; `[[nodiscard]]` warns if you ignore a return value.

### Purposes

- To provide compiler hints and warnings.
- To mark deprecated or unsafe APIs.
- To indicate that a return value must be used.
- To suppress warnings for unused variables.

### Syntax Rules and Structure

**General Syntax**
```cpp
[[deprecated("use new_function instead")]]
void old_function();

[[nodiscard]] int compute();
```

**Component Breakdown**

| Attribute | Meaning |
|-----------|---------|
| `[[noreturn]]` | Function never returns. |
| `[[deprecated]]` | Function/type is deprecated. |
| `[[nodiscard]]` | Return value should not be ignored. |
| `[[maybe_unused]]` | Suppress unused warnings. |
| `[[fallthrough]]` | Intentional fallthrough in `switch`. |

**Syntax Rules**
- Attributes are enclosed in double square brackets.
- They can take arguments (e.g., `[[deprecated("reason")]]`).
- Multiple attributes can be applied.

**Constraints and Limitations**
- Unknown attributes are ignored (with a warning).
- Attribute support varies by compiler.

### Annotated Code Example

```cpp
#include <iostream>

[[deprecated("use new_api() instead")]]
void old_api() { std::cout << "old\n"; }

[[nodiscard]] int compute() { return 42; }

int main() {
    old_api();                         // warning
    compute();                         // warning: return value ignored
    int x = compute();                 // OK
    std::cout << x << '\n';
}
```

**Expected Output** (compiler warnings are issued)
```
old
42
```

**Why this output?**  
`old_api` is called despite the deprecation warning; `compute()`’s return value is ignored in one call (warning) and used in another.

### Real-World Cases

- **API evolution** – marking old functions deprecated.
- **Safety** – `[[nodiscard]]` for important return values.
- **Compiler optimisation** – `[[likely]]`/`[[unlikely]]` (C++20).
